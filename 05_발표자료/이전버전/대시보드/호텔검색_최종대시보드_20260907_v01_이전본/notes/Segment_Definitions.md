# 세그먼트 분류 기준

## 목적과 단위

검색의도는 누구에게 어떤 개선안을 제시할지 정하기 위한 사용자 단위 잠재 분류입니다. 검색결과 성과군은 세션의 결과를 비교하기 위한 사후 분류입니다. 서로 대체할 수 없으며, 성과군을 무작위 실험군으로 해석하지 않습니다.

## 성과군: 현재 코드에서 실제 집계

세션 안의 검색을 `search_time`, `search_id` 오름차순으로 정렬합니다.

| 코드 | 이름 | 필요충분 조건 | 전체 세션 수 |
| --- | --- | --- | --- |
| SG1 | 직접 성공 | 첫 결과 수 > 0 AND 세션 내 hotel_click 존재 | 630 |
| SG2 | 결과 노출·미선택 | 첫 결과 수 > 0 AND 세션 내 hotel_click 없음 | 231 |
| SG3 | 재검색 회복 | 첫 결과 수 = 0 AND 이후 검색 중 결과 수 > 0 존재 | 92 |
| SG4 | 지속 실패 | 첫 결과 수 = 0 AND 이후 검색 중 결과 수 > 0 없음 | 47 |

검색이 있는 세션당 하나만 부여하며 합계는 1,000세션입니다. SG1의 성공은 클릭 기준으로 예약 성공이 아닙니다. 첫 검색에 결과가 있었다면 도중에 0건 검색을 경험해도 SG1/SG2입니다. SG3는 즉시 다음 검색이 아니라 이후 어느 검색에서든 결과를 찾으면 포함합니다. SG4는 재검색을 하지 않은 경우도 포함하며 이탈로 단정하지 않습니다. 월 필터는 세션 시작 월 기준이고 세션 전체 이력을 유지합니다.

## 의도군: 기존 문서 정의와 현재 연결 상태

| 코드 | 의도 | 문서의 행동 경향 |
| --- | --- | --- |
| budget_flexible | 예산 조정 가능 | 최대가격 상향·가격 필터 해제 |
| option_count_flexible | 요구 옵션 수 조정 가능 | 요구 옵션 수 감소 |
| location_flexible | 위치 변경 가능 | 인접·대체 지역 선택 |
| condition_keeper | 조건 유지 선호 | 동일 조건 반복·조건 강화 |
| query_reframer | 검색 표현 수정 선호 | 검색어 수정·연관어 선택 |
| rapid_resolver | 여러 조건을 바꿔 해결 선호 | 지역·가격·필터 복합 변경 |

기존 10,000명 설계 문서는 신호별 확률 점수 → 사용자당 intent_segment 1개를 seed로 추출 → control/treatment에 동일하게 층화 배정하는 절차를 정의합니다. 이는 현재 1,000명 데이터의 실행 결과를 의미하지 않습니다. 여러 신호가 나타나도 6개 군에 모두 중복 배정하는 규칙이 아닙니다. 현재 연결 자료만으로 확률식·가중치·seed·임계값·실제 사용자 매핑을 재현할 수 없어 의도군별 수치와 효과를 표시하지 않습니다.

동일 조건 반복을 몇 회 이상으로 볼지, 빠른 해결을 몇 초 이내로 볼지에 대한 임계값을 임의로 만들지 않았습니다. 행동 예시는 의도를 확정하는 판정식이 아닙니다. 실험을 연결할 때 실제 생성 코드·버전·seed·user_id별 intent_segment·배정 시점·실험 variant가 필요합니다. 현재 실험의 처치 후 행동을 이용해 실험 전 의도를 역으로 정하지 않습니다.

# OTA 플랫폼 검색 필터 개선을 위한 데이터 조사

> Team I 미니프로젝트 참고자료
> 조사 목적: 호텔 공급 데이터와 사용자 탐색 행동을 활용해 위치·카테고리 기반 검색 필터 개선 가능성을 검토한다.

## 조사 결론

Expedia를 제외해도 활용 가능한 자료는 있다. 다만 **호텔 속성·검색 노출·필터 사용·클릭·예약을 모두 포함하는 단일 공개 데이터셋은 찾기 어렵다.**

이번 프로젝트에는 다음 조합이 가장 현실적이다.

1. **Trivago RecSys 2019**로 실제 필터 사용과 검색 행동 분석
2. **Rakuten Travel 데이터**로 일본 여행 목적·동행 유형별 선호 속성 분석
3. 기존 일본 호텔 공급 데이터에 **일본 공공데이터와 OSM 위치 정보** 결합
4. 연결되지 않는 행동·예약 구간은 가상 데이터로 보완

### 분석 Key Question

> 공개된 OTA 행동·호텔 데이터를 이용해 위치·가격·숙소 특성 필터가 사용자의 검색 성공과 클릭 가능성을 높이는지 검증할 수 있는가?

결론적으로 **부분적으로 가능하지만, 복수 데이터셋을 역할별로 분리해 사용해야 한다.**

### Trivago RecSys Challenge 2019

Expedia 외 자료 중 이번 프로젝트와 가장 가까운 데이터다.

주요 필드는 다음과 같다.

- `user_id`, `session_id`, `timestamp`, `step`
- `search for destination`, `search for POI`, `search for item`
- `filter selection`, `current_filters`, `change of sort order`
- `interaction item info/image/rating/deals`
- `clickout item`
- `impressions`, `prices`
- `city`, `platform`, `device`
- `item_id`, `properties`

| 프로젝트 테이블 | Trivago 대응 데이터 |
|---|---|
| `search_session` | `session_id`, 사용자, 도시, 기기, 플랫폼 |
| `search_query` | 목적지·호텔·POI 검색 |
| `search_result_impression` | `impressions`, `prices` |
| `user_event_log` | 필터, 정렬, 이미지·정보·후기 상호작용 |
| `hotel_master` | `item_id`, 호텔 속성 |
| 클릭 결과 | `clickout item` |

`clickout`은 예약 완료가 아니라 Trivago에서 제휴 예약 사이트로 이동한 행동이다. 따라서 Booking Conversion보다 **검색 후 클릭 성공률**을 중심으로 분석하는 것이 적절하다.

- [Trivago RecSys 2019 데이터 정의](https://github.com/recsyschallenge/2019/blob/master/docs/problem_definition.md)
- [Trivago 공식 벤치마크 저장소](https://github.com/trivago/recsys-challenge-2019-benchmarks)

### Rakuten Travel Data Release

일본 숙소와 일본어 사용자 선호를 분석할 수 있다는 점에서 매우 유용하다.

- 여행 목적과 동행 유형
- 숙소·객실·플랜 ID
- 객실 유형과 객실명
- 위치·객실·식사·목욕·서비스·시설·종합 평점
- 후기 내용과 숙소 답변
- 숙소 마스터

이를 이용하면 가족여행과 출장의 중요 필터 차이, 온천·조식·객실·위치 속성의 만족도, 사용자 목적별 필터 우선순위 등을 분석할 수 있다. NII 또는 ALAGIN을 통해 신청하고 다운로드 승인을 받아야 한다.

- [Rakuten 공식 데이터 안내](https://ai.rakuten.com/rakuten-data-release/)

### 일본 공공데이터와 OpenStreetMap

기존 일본 호텔 공급 데이터에 다음 정보를 보강할 수 있다.

- 위도·경도와 행정구역
- 역·관광명소까지의 거리
- 호텔·료칸 구분
- 휠체어 이동 및 배리어프리 정보
- 관광청 배리어프리 인증 여부

관광청 숙박여행통계는 지역별 숙박객·객실가동률·국내외 이용객을 제공하지만 집계 데이터이므로 개별 호텔 필터 분석보다는 시장 배경 설명에 적합하다.

- [국토교통성 숙박시설 CSV](https://www.hokoukukan.go.jp/metadata/map/80)
- [관광청 배리어프리 인증시설](https://www.mlit.go.jp/kankocho/seisaku_seido/kokorono_barrier-free/index.html)
- [OpenStreetMap Japan](https://www.openstreetmap.jp/)
- [일본 관광청 숙박여행통계](https://www.mlit.go.jp/kankocho/tokei_hakusyo/shukuhakutokei.html)

### Booking.com Multi-Destination Trips

100만 건 이상의 익명 예약과 연속 방문 도시를 포함한다. 사용자 국가, 호텔 국가, 도시, 숙박일, 기기, 제휴 채널을 이용해 해외·국내 여행과 다중 목적지 이동 패턴을 분석할 수 있다.

검색어, 필터, 노출 결과, 호텔 시설은 없으므로 **위치 추천 또는 여행 코호트 분석용 보조 데이터**로 적합하다. 비상업적 연구용 이용조건을 확인해야 한다.

- [Booking.com 공식 데이터 저장소](https://github.com/bookingcom/ml-dataset-mdt)

### HotelRec

약 2,189만 명의 사용자, 36만 개 호텔, 약 5,026만 건의 TripAdvisor 후기를 포함한다. 위치·서비스·객실·청결 등 세부 만족 속성과 추천 모델을 연구하는 데 유용하다.

실제 검색 노출과 필터 선택이 없기 때문에 “어떤 필터를 제공해야 하는가”를 찾는 데는 도움이 되지만 “필터 사용이 클릭을 높였는가”는 검증할 수 없다.

- [HotelRec 논문 및 데이터 안내](https://arxiv.org/abs/2002.06854)

### ViHoRec

Booking.com, Traveloka, Ivivu에서 수집한 베트남 호텔 추천 데이터로 6,832명, 560개 호텔, 18,267개 상호작용을 포함한다. 규모가 작아 미니프로젝트 실습과 콜드스타트 비교에는 적합하지만 일본 호텔의 실제 필터 개선 효과를 직접 대표하지는 못한다.

- [ViHoRec 논문 및 데이터](https://arxiv.org/abs/2607.12946)

## 2. 검색·호텔 데이터 분석 사례

| 사례 | 핵심 내용 | 프로젝트에서 참고할 점 |
|---|---|---|
| Trivago RecSys Challenge | 세션 내 필터·재검색·호텔 상호작용으로 다음 클릭 호텔 예측 | 필터 적용 전후 클릭, 재검색, 결과 순위 분석 |
| OTA 필터 UI 실험 | 1,492명을 대상으로 정렬·필터 제공 여부에 따른 호텔 선택 변화 분석 | 필터를 단순 보조 기능이 아니라 선택을 바꾸는 개입으로 정의 |
| Airbnb 검색 랭킹 | 검색·예약 행동을 이용한 랭킹, 개인화, 위치 편향, 신규 숙소 문제 연구 | 상위 노출 편향과 신규 호텔 콜드스타트 통제 |
| Booking.com 실험 체계 | 검색·상품 기능을 온라인 대조실험으로 평가 | CTR뿐 아니라 A/B 테스트와 Guardrail 포함 |
| Hotel2vec | 클릭에 숙소 속성·편의시설·지리 정보를 결합 | 호텔 공급 속성과 사용자 행동을 결합해야 함 |

### OTA 필터 기능의 선택 효과

1,492명을 대상으로 한 실험에서는 정렬·필터 기능을 제공할 경우 이용자가 단순히 상단 호텔을 선택하기보다 필터 대상 속성을 더 고려했다.

- 가격 필터·정렬을 제공하면 저렴한 객실 선택 증가
- 평점 필터·정렬을 제공하면 평점이 높은 객실 선택 증가
- 선택이 일부 상위 호텔에 집중되지 않고 더 균형 있게 분산

이는 필터가 기존 선호를 반영하기만 하는 것이 아니라 **사용자가 중요하게 생각하는 선택 기준 자체를 바꿀 수 있음**을 의미한다.

- [OTA 필터·정렬 실험 연구](https://ir.cwi.nl/pub/25237/)

### Airbnb 검색 랭킹 사례

Airbnb는 사용자와 숙소 임베딩을 이용해 장·단기 관심사를 반영하고, 오프라인 평가 후 온라인 실험으로 검증했다. 또한 상위에 노출됐기 때문에 클릭·예약된 것인지 실제 선호 때문인지 구분하는 위치 편향과 신규 숙소 콜드스타트 문제를 다뤘다.

- [Airbnb 실시간 개인화 연구](https://www.kdd.org/kdd2018/accepted-papers/view/real-time-personalization-using-embeddings-for-search-ranking-at-airbnb)
- [Airbnb 검색 랭킹 연구](https://www.kdd.org/kdd2019/accepted-papers/view/applying-deep-learning-to-airbnb-search)

### Booking.com 검증 방식

Booking.com은 제품 변경을 온라인 대조실험으로 검증하고 과거 실험의 성공과 실패를 축적하는 체계를 운영해 왔다. 필터 개선도 단순 CTR 상승만 확인할 것이 아니라 재검색률, 결과 없음 비율, 예약 시도율과 함께 평가해야 한다.

- [Booking.com 온라인 실험 연구](https://arxiv.org/abs/1710.08217)

## 3. 도움이 될 아티클과 자료

| 자료 | 주요 내용 | 활용 방법 |
|---|---|---|
| Baymard 여행 검색 UX 연구 | 호텔 등급, 침대 크기, 주차장 등 여행 특화 필터가 없으면 사용자가 이탈할 수 있음 | 필터 후보 선정과 사용자 인터뷰 문항 작성 |
| Algolia 필터 UX 가이드 | 필터별 결과 수, 인기순 배치, 필터·정렬 병행, 쉬운 해제 | 필터 UI 개선안 설계 |
| Trivago 데이터 정의 | 검색·필터·정렬·노출·클릭 이벤트 구조 | 가상 데이터 스키마와 이벤트 로그 설계 |
| Booking.com 실험 연구 | 온라인 실험과 데이터 품질 관리 | KPI·A/B 테스트 설계 |
| Rakuten Data Release | 일본 여행 목적·동행자·호텔 평가 항목 | 사용자 세그먼트와 필터 우선순위 설계 |

Baymard의 숙박 검색 사용성 조사에서는 호텔 등급, 침대 크기, 주차장 등의 필터 부재가 사용자의 탐색 포기나 불필요한 상세페이지 방문으로 이어질 수 있다고 설명한다. 최소 5~10개의 업종 특화 필터 제공을 권장한다.

- [Baymard 여행 검색 UX 연구](https://baymard.com/blog/travel-site-ux-best-practices)

Algolia는 필터별 예상 결과 수를 동적으로 보여주고, 필터와 정렬을 동시에 유지하며, 선택한 필터를 검색을 다시 시작하지 않고 쉽게 제거할 수 있어야 한다고 제안한다.

- [Algolia 검색 필터 UX 가이드](https://www.algolia.com/blog/ux/search-filter-ux-best-practices)

## 4. 프로젝트 적용 권고안

| 분석 영역 | 권장 데이터 |
|---|---|
| 실제 검색·필터 행동 | Trivago RecSys 2019 |
| 일본 사용자 목적·동행 유형 | Rakuten Travel |
| 일본 호텔 속성 | 기존 `Hotellist_supplier_japan_clean.xlsx` |
| 위치·POI | OpenStreetMap 및 일본 공공데이터 |
| 배리어프리 | 국토교통성·관광청 데이터 |
| 예약 전환 | Booking.com MDT 또는 가상 `booking_funnel` |
| 실험군·대조군 | 가상 `experiment_assignment` |

Trivago의 익명 `item_id`와 현재 일본 호텔 데이터의 `hotel_id`는 직접 연결할 수 없다. 따라서 다음처럼 두 분석을 분리하는 것이 안전하다.

- **실데이터 검증:** Trivago로 필터 사용과 검색·클릭 행동 관계 분석
- **일본 적용 검증:** 일본 호텔 공급 데이터와 공공데이터에 가상 사용자 세션을 결합해 위치·카테고리 필터 개선 효과 시뮬레이션

## 추가 확인이 필요한 사항

Rakuten처럼 대학·연구 목적의 신청 절차가 필요한 데이터도 이번 프로젝트에서 사용할 수 있는지 확인해야 한다. 사용할 수 없다면 즉시 다운로드 가능한 데이터만으로 후보를 다시 좁히는 것이 적절하다.

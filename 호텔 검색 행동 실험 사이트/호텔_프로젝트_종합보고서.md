# StayTrace 호텔 프로젝트 종합 보고서

작성일: 2026-08-31  
프로젝트 폴더: `호텔/`

## 1. 프로젝트 개요

StayTrace는 일본 호텔을 찾는 과정에서 사용자의 검색 의도, 검색 조건, 결과 노출, 상세 조회, 찜, 장바구니, 예약 완료까지의 행동 흐름을 관찰하기 위한 연구용 웹 애플리케이션이다. 실제 숙박 예약 서비스처럼 자유롭게 탐색할 수 있지만 실제 결제나 실제 예약은 발생하지 않는다.

이 프로젝트는 단순한 호텔 목록 화면을 만드는 데 목적이 있지 않다. 사용자가 원하는 조건과 화면에 제시되는 정보가 일부 어긋날 때 탐색 행동과 전환이 어떻게 달라지는지, 어느 단계에서 재검색하거나 이탈하는지를 구조화된 이벤트로 남겨 분석할 수 있는 실험 환경을 만드는 것이 핵심이다.

## 2. 기획 의도와 목적

### 2.1 문제의식

일반적인 예약 데이터에는 최종 구매 결과는 남지만, 사용자가 어떤 조건으로 탐색했고 무엇을 비교했으며 왜 중간에 조건을 바꾸거나 이탈했는지는 충분히 남지 않는다. 검색 결과의 노출 순서와 객실 조건의 불일치도 실제 행동에 영향을 줄 수 있지만, 결과 데이터만으로 그 과정을 설명하기 어렵다.

### 2.2 목적

- 검색부터 예약 완료까지의 전체 사용자 여정을 이벤트 단위로 기록한다.
- 검색 조건, 노출 순위, 상세 조회, 찜·장바구니, 예약 행동의 관계를 분석한다.
- 정상 정보와 일부 조건 불일치가 포함된 실험군을 재현 가능한 방식으로 비교한다.
- 관리자 화면과 CSV 내보내기를 통해 후속 분석이 가능한 데이터를 만든다.
- 실제 개인정보, 결제, 객실 재고를 다루지 않는 안전한 연구용 환경을 유지한다.

### 2.3 기대 활용

- 노출 대비 클릭률과 상세 조회 전환 분석
- 검색 무결과율과 재검색 패턴 분석
- 필터·정렬 변경 및 찜·장바구니 행동 분석
- 예약 시작 및 완료 전환율 분석
- 조건 불일치가 클릭·이탈·전환에 미치는 영향 비교

## 3. 개발 과정

### 3.1 1단계: 로컬 행동 수집 프로토타입

루트의 `app/`, `scripts/`, `tests/`, `data/`, `run.py`는 Python 기반 초기 프로토타입이다. SQLite를 중심으로 사용자, 세션, 호텔, 검색, 검색 필터, 이벤트, 리뷰, 예약 데이터를 설계하고 검색부터 예약까지의 기본 흐름을 검증했다.

이 단계의 핵심 성과는 화면 완성도보다 분석 가능한 이벤트 구조를 먼저 확인한 것이다. 검색 계보, 노출 중복 방지, 세션 단위 행동 순서, 관리자 지표, CSV 추출 방식이 이때 구체화되었다.

### 3.2 2단계: 분석 모델 점검

`model-check.pbix`와 `pbix-inspect/`는 Power BI 모델과 메타데이터를 점검하기 위한 자료다. 웹앱에서 수집한 데이터가 후속 시각화와 행동 분석에 연결될 수 있는지 확인하는 용도로 남겨 두었다.

### 3.3 3단계: 웹 서비스 고도화

`cloud-site/`는 현재의 주 애플리케이션이다. Next.js, React, TypeScript 기반으로 UI를 고도화하고, Cloudflare 환경에 맞춘 빌드·배포 구조와 D1/Drizzle 데이터 계층을 추가했다.

주요 구현 내용은 다음과 같다.

- 일본 호텔 카탈로그와 객실·옵션 데이터 제공
- 검색, 필터, 정렬, 상세 조회, 찜, 장바구니, 예약 흐름 구현
- 참여자 및 세션 상태 관리
- 행동 이벤트와 실험 조건 기록
- 관리자용 데이터 콘솔과 내보내기 기능
- 공개 프로젝트 보고서 및 제작자료 다운로드 제공
- 테스트, 배포, 운영·보안, 요구사항 이력을 문서화

### 3.4 4단계: 재현성과 인수인계 문서화

제품 명세, 코드 지도, 데이터·이벤트 설계, 테스트·배포 절차, 운영 원칙, 요구사항 변경 이력, 릴리스 체크리스트를 제작자료로 구성했다. 현재 정본은 `cloud-site/docs/site-production-kit/`이며, 확인용 모음은 `cloud-site/보고서_및_제작자료/`, 사이트 다운로드용 사본은 `cloud-site/public/`에 있다.

## 5. 데이터 및 실험 설계 원칙

1. 행동의 결과뿐 아니라 시간순 과정을 기록한다.
2. 검색 조건은 당시 상태를 스냅샷으로 보존한다.
3. 같은 검색에서 동일 호텔의 노출이 중복 집계되지 않도록 한다.
4. 실험 조건은 결정적 방식으로 부여해 같은 입력에서 재현 가능하게 한다.
5. 실제 개인정보, 실제 결제정보, 비밀 키와 단기 배포 자격 증명은 수집·배포 자료에서 제외한다.
6. 공개용 호텔 정보와 연구용 가상·실험 데이터를 명확히 구분한다.

## 6. 실행과 검증

### 현재 웹앱

```powershell
cd cloud-site
npm install
npm run dev
```

검증 명령:

```powershell
npm run lint
npm test
```

Node.js 22.13.0 이상이 필요하다. 배포 전에는 `cloud-site/보고서_및_제작자료/02-제작문서/09-release-checklist.md`를 확인한다.

### 초기 Python 프로토타입

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts\seed_hotels.py
python run.py
```

## 7. 현재 한계와 주의사항

- 실제 예약, 결제, 객실 재고 연동 기능은 없다.
- 운영 서비스 수준의 인증·권한·개인정보 동의 체계는 별도 설계가 필요하다.
- 호텔 및 객실 데이터에는 연구용 가상 데이터와 실험 변형이 포함될 수 있다.
- 브라우저 종료 이벤트는 환경 특성상 항상 전송된다고 보장할 수 없다.
- 소규모 실험 결과를 실제 상용 서비스 전체 이용자의 행동으로 일반화해서는 안 된다.

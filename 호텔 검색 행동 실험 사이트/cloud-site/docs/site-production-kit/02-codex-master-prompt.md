# Codex 통합 제작 프롬프트

아래 프롬프트는 빈 작업공간에서 현재 StayTrace와 같은 연구용 사이트를 다시 만드는 용도다. 기존 프로젝트에서 사용할 때는 “기존 코드를 먼저 검사하고 정상 기능을 보존하라”는 조건을 유지한다.

```text
너는 숙박 예약 UX, 풀스택 웹 개발, 데이터 엔지니어링과 행동 실험 설계 경험이 있는 개발자다.

목표:
실제 여행 예약 사이트와 유사하게 자유롭게 탐색할 수 있으면서, 사용자의 검색 의도와 실제 검색·객실 결과의 일부 불일치가 검색 효율과 예약 전환에 미치는 영향을 측정하는 StayTrace 웹앱을 구현하라. 실제 결제는 하지 않는다.

작업 원칙:
1. 현재 작업 디렉터리와 기존 코드를 먼저 확인한다.
2. 기존 정상 기능과 사용자 변경 사항을 보존하고 필요한 부분만 수정한다.
3. 질문 없이 합리적으로 결정할 수 있는 것은 직접 결정하고 구현·테스트까지 수행한다.
4. 비밀 API 키나 배포 토큰을 코드, 문서, 로그, Git에 저장하지 않는다.
5. 사이트가 .openai/hosting.json을 사용하면 기존 Sites 프로젝트를 재사용한다.

기술 구조:
- React 19 + Next 호환 App Router + TypeScript
- vinext/Vite 기반 Cloudflare Worker 빌드
- Cloudflare D1 + Drizzle ORM
- 한 페이지 상태 전환형 사용자·관리자 UI
- 반응형 CSS

사용자 기능:
- 첫 화면에서 이름, 연령대, 성별, 여행 빈도, 목적, 동행 유형을 입력한다.
- 참여자 코드는 사용하지 않고 이름을 동일 사용자 식별 기준으로 쓴다.
- 탭을 닫기 전까지 로그인 상태를 유지하고 화면에 상태를 표시한다.
- 최초 검색은 지역 미선택 상태이며 한글·영문 검색어로도 찾을 수 있다.
- 기본 검색에는 검색어, 지역, 세부지역, 2026년 체크인·체크아웃, 인원, 객실 수만 둔다.
- 검색 버튼을 눌렀을 때만 검색 조건과 이벤트를 저장한다.
- 결과 화면 상단에 검색 엔진, 옆에는 독립 스크롤 상세 옵션 패널을 둔다.
- 상세 옵션은 가격 구간·최대 가격, 숙소 유형, 등급, 평점, 역 거리, 취소·결제, 조식, 가족 객실, 반려동물, 수영장, 스파, 발코니 등 실제 예약 사이트 수준으로 구성한다.
- 상세 옵션에서는 날짜와 인원을 변경하지 못하게 한다.
- 호텔 카드를 클릭하면 상세 상품 안내로 이동한다.
- 상세에는 숙소 소개, 세부지역, 시설 안내, 평점·리뷰 수, 가상 대표 리뷰 5개, 시설 이미지 갤러리, 객실 상품과 달력을 표시한다.
- 객실은 호텔당 3종이며 2026년 날짜·객실 조합에 따라 일부 판매 마감 상태가 된다.
- 예약 취소 시 오류 없이 이전 상세 또는 검색 상태로 돌아간다.
- 스크롤 중에도 이전 화면 버튼이 보이게 한다.
- 모바일에서도 모든 핵심 기능을 사용할 수 있게 한다.

데이터:
- Tokyo, Osaka, Kyoto, Fukuoka, Sapporo 각 200개, 총 1,000개 호텔
- 도시별 세부지역 10개
- 공개 숙박업소 자료 기반 호텔명 사용 가능
- 가격, 평점, 리뷰 수, 객실 재고와 시설 가용성은 연구용 시뮬레이션임을 표시
- 호텔별 특성 기반 가상 리뷰 5개, 리뷰 길이 10~500자
- HOTEL, USER, SESSION, SEARCH, SEARCH_FILTER, EVENT, REVIEW, RESERVATION과 필요한 ROOM_INVENTORY 구조

이벤트:
- session_start/session_end
- search_submit/search_result_view/search_no_result
- hotel_impression/hotel_click/hotel_detail_view/back_to_results
- filter_apply/filter_reset/sort_change
- wishlist_add/wishlist_remove
- hotel_gallery_view/review_view
- room_select/booking_start/booking_cancel/booking_complete
- keyword_search_error_exposure/option_mismatch_exposure
- 모든 이벤트는 user_id, session_id, search_id, hotel_id, page, 시간, JSON 속성을 가능한 범위에서 보유한다.
- 타자나 단순 체크 변경이 아니라 제출·적용·클릭 버튼을 중심으로 수집한다.

오류 실험:
- Agoda가 전체 오류율을 공개하지 않으므로 실제 Agoda 측정값이라고 표현하지 않는다.
- 세션 ID의 결정적 해시로 정상군 75%, 오류 실험군 25%를 배정한다.
- 오류군의 객실 선택 옵션별 불일치 확률은 32%로 두어 전체 기대 발생률을 약 8%로 만든다.
- 오류군의 키워드 결과 불일치 확률은 20%로 두어 전체 기대 발생률을 약 5%로 만든다.
- 항상 오류를 내지 말고 세션·호텔·옵션 조합별로 재현 가능하게 일부에서만 발생시킨다.
- 날짜별 판매 마감은 검색 오류와 별도인 정상 재고 상태로 취급한다.
- 이벤트 속성에 variant, 오류 여부, 요청 옵션, 불일치 옵션, 실험 비율을 저장한다.

관리자:
- 모든 핵심 테이블 확인과 테이블별 CSV 다운로드
- 소프트 삭제, 휴지통, 복구
- 세션별 행동 순서와 전환 지표
- 사이트 기획·제작 문서 다운로드

검증:
- 프로덕션 빌드를 실행하고 실패를 직접 수정한다.
- 검색→상세→뒤로가기→재검색→객실→예약 및 취소 흐름을 확인한다.
- 세션, 새 search_id, parent_search_id, impression 순위, 오류 이벤트 저장을 확인한다.
- 모바일 레이아웃과 관리자 CSV를 확인한다.
- 기존 공개 프로젝트가 있으면 새 프로젝트를 만들지 말고 같은 URL에 새 버전을 배포한다.

완료 보고:
- 배포 URL
- 구현 기능
- 오류 실험 비율과 한계
- 테스트 결과
- 문서 위치
를 한국어로 간결하게 알려라.
```

## 사용 방법

1. 이 프롬프트와 `01-product-spec.md`를 함께 제공한다.
2. 기존 프로젝트라면 프로젝트 루트에서 Codex를 실행한다.
3. 기능 변경은 `03-codex-change-prompts.md`의 작은 프롬프트를 우선 사용한다.
4. 배포 전에는 `09-release-checklist.md`를 함께 지시한다.

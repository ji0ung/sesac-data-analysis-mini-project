## 1. 프로젝트 개요

StayTrace는 일본 숙소 검색 과정에서 검색 조건과 실제 예약 가능한 객실 조건이 일부 불일치할 때 사용자의 검색 효율과 예약 전환에 어떤 변화가 생기는지 관찰하기 위한 연구용 웹앱이다. 실제 예약 서비스가 아니며 결제도 발생하지 않는다.

핵심 연구 질문은 다음과 같다.

1. 사용자가 선택한 시설·정책 옵션과 객실 상세 조건이 다를 때 재검색 횟수가 증가하는가?
2. 옵션 불일치가 객실 선택률과 예약 완료율을 낮추는가?
3. 키워드 검색 결과의 누락 또는 비관련 결과 삽입이 탐색 시간과 클릭 순위에 영향을 주는가?
4. 예약 불가 객실 표시가 대체 객실 선택과 이탈에 어떤 영향을 주는가?

## 2. 서비스 구성

### 사용자 화면

- 참여자 정보 입력: 이름, 연령대, 성별, 여행 빈도, 여행 목적, 동행 유형
- 기본 검색: 키워드, 목적지, 세부지역, 체크인·체크아웃, 인원, 객실 수
- 검색 결과: 결과 상단 검색 엔진, 사이드 상세 옵션, 카드형 숙소 목록, 별점·리뷰 수·가격 오름차순·가격 내림차순 정렬
- 상세 옵션: 가격, 평점, 역 거리, 취소·결제 정책, 조식, 가족 객실, 반려동물, 수영장, 스파, 발코니 등
- 호텔 상세: 숙소 소개, 시설 이미지, 시설 안내, 리뷰, 달력, 객실 상품과 예약 가능 여부
- 예약 흐름: 객실 선택, 예약 확인, 완료 또는 취소 후 이전 단계 복귀
- 찜·장바구니: 로그인 탭 동안 찜 숙소와 객실 상품을 보관하고 목록에서 삭제·상세 조회·예약 진행

### 관리자 화면

- HOTEL, ROOM, SEARCH, SEARCH_FILTER, USER, EVENT, SEARCH_RESULT, BOOKING 데이터 확인
- 테이블별 CSV 다운로드
- 사용자·검색어·테이블·개별 칼럼 필터와 다중 선택을 이용한 데이터 소프트 삭제 및 휴지통 일괄 복구
- 필터 결과 즉시 일괄 삭제와 사용자·로그인 세션별 행동 과정을 시간순으로 보여주는 USER JOURNEY 탭
- 검색 효율, 객실 선택률, 예약 전환율 요약
- 본 기획 보고서 다운로드

- 시설 이미지는 숙소 유형과 시설 특성을 바탕으로 생성한 이미지이며 실제 호텔 사진이 아니다.

## 4. 검색 및 오류 실험 설계

### 실제 정보와 가상 정보 구분

| 구분 | 항목 | 처리 방식 |
|---|---|---|
| 실시간 실제 확인 정보 | 상세 화면의 숙소명, 실제 주소, 위도·경도, 제공 가능한 평점과 평가 수, 운영 상태, 숙소 유형, 공식 웹사이트, 원본 지도 링크 | 호텔 상세 진입 시 Google Places API로 조회하며, 키 권한 또는 매칭 문제 시 OpenStreetMap Nominatim 실시간 조회로 대체한다. 응답은 화면에만 표시하고 장기 저장하지 않는다. |
| 공개자료 참고 정보 | 검색 목록의 호텔명과 도시 | 기존 관광 디렉터리와 2026-08-27 수집 OpenStreetMap 숙박업소 명칭을 사용한다. 개별 실시간 검증 전에는 참고값으로 취급한다. |
| 가상 연구 데이터 | 세부지역, 주소 대체값, 등급, 10점 평점, 리뷰 수, 가격, 역 거리, 시설, 객실 유형·면적·침대·전망, 객실 재고, 취소·결제 정책, 예약 상태 | 실제 예약·재고 API와 연결되지 않은 결정적 시뮬레이션 값이다. |
| 생성 이미지 | 대표 이미지와 시설·객실 갤러리 | 숙소 특성 기반 연구용 이미지이며 실제 호텔 사진이 아니다. |
| 가상 리뷰 | 호텔별 대표 리뷰 5개 | 호텔 특성을 반영해 생성한 연구용 문장이다. |
| 실제 연구 로그 | 참여자 입력, 검색 조건, 클릭, 옵션 적용, 상세 조회, 객실 선택 등 | 참여자가 실제로 수행한 행동과 입력 시각을 기록한다. 단, 예약 완료는 실제 거래가 아닌 실험 완료 이벤트다. |

실제 정보는 API 제공 범위와 매칭 결과에 따라 일부 호텔에서 조회되지 않을 수 있다. 조회 실패 시 실제값을 임의 생성하지 않고 `실제 정보 조회 결과 없음`으로 표시한다. Google 정책에 따라 Places 응답은 카탈로그에 영구 저장하지 않으며, 각 상세 화면에서 사용된 출처와 원본 지도 링크를 함께 제공한다. OpenStreetMap 출처에는 평점·평가 수가 없으므로 해당 값은 제공되지 않음으로 표시한다.

Agoda는 필터 또는 검색 의도 불일치의 전체 발생률을 공식적으로 공개하지 않는다. 따라서 본 서비스의 수치는 Agoda 실제 오류율을 복제한 값이 아니라, Agoda 파트너 문서에서 확인되는 객실 시설 표시 불일치와 채널별 재고 차이를 참고해 과도하지 않은 빈도로 보정한 연구용 추정치다.

### 적용 비율

| 구분 | 설계값 | 전체 사용자 기준 기대 발생률 |
|---|---:|---:|
| 정상 세션 | 75% | 의도적 오류 없음 |
| 오류 실험 세션 | 25% | 일부 검색·객실 조건 오류 가능 |
| 객실 옵션 불일치 | 오류 세션에서 옵션별 32% | 선택 옵션당 약 8% |
| 키워드 결과 불일치 | 오류 세션에서 검색별 20% | 키워드 검색당 약 5% |

객실 옵션 오류는 선택한 모든 옵션에 동일한 방식으로 적용 가능하지만 항상 발생하지 않는다. 예를 들어 스파를 선택했어도 일부 세션·호텔 조합에서만 남은 객실에 스파가 없도록 표시된다. 오류 여부는 세션, 호텔, 옵션 조합을 해시한 결정적 값으로 계산하므로 같은 조건에서는 재현 가능하다.

예약 불가 객실은 오류가 아니라 날짜별 재고 상태로 별도 처리한다. 2026년 날짜와 호텔·객실 조합을 기준으로 일부 객실을 판매 마감 상태로 표시한다.

## 5. 비율 조정 근거와 한계

- Agoda 공식 고객 안내는 호텔명 검색 결과가 조건과 일치하며, 없을 경우 대체 숙소를 제안할 수 있다고 설명한다.
- Agoda 파트너 문서는 활성화되지 않은 객실 유형에 남은 시설 정보 등으로 잘못된 시설이 표시될 수 있다고 안내한다.
- Agoda 개발자 문서는 웹사이트와 API의 객실 재고를 직접 비교하지 말라고 안내하며 채널 간 재고 차이가 존재할 수 있음을 보여준다.
- OTA 연구는 호텔이 판매 채널별로 객실 가용성을 다르게 관리할 수 있음을 설명한다.
- 공개 자료만으로 전체 검색 중 실제 오류 비율을 산출할 수 없으므로 5~8%는 사실 측정값이 아니라 보수적인 연구 설계값이다.

기존 설계는 오류 실험 세션 50%, 해당 세션 옵션별 35%로 전체 기대 발생률이 약 17.5%였다. 이는 일반적인 예약 사이트 경험보다 오류가 지나치게 자주 보일 수 있어, 이번 개편에서 옵션 약 8%, 키워드 약 5%로 낮췄다.

## 6. 이벤트 수집 원칙

- 타자 입력이나 체크박스 변경 자체는 이벤트로 저장하지 않는다.
- 사용자가 `검색하기` 또는 `선택 옵션 적용` 버튼을 눌렀을 때 `search_submit`을 한 번 기록한다.
- 최초 검색과 결과 화면의 상세 옵션 적용은 `submit_trigger`로 구분한다.
- 호텔 노출, 호텔 클릭, 상세 조회, 이미지 탐색, 객실 선택, 예약 시작, 취소, 예약 완료를 단계별 이벤트로 기록한다.
- 검색 오류 노출은 `keyword_search_error_exposure`, 객실 옵션 불일치는 `option_mismatch_exposure`로 구분한다.

## 7. 주요 성과 지표

- 검색 효율: 예약 완료까지 검색 제출 횟수, 호텔 상세 진입 전 검색 횟수
- 탐색 행동: 호텔 노출 순위, 카드 클릭률, 상세 페이지 체류 및 객실 선택률
- 오류 영향: 정상군과 오류군의 재검색률, 이탈률, 객실 선택률 차이
- 예약 성과: 예약 시작률과 예약 완료율
- 복구 행동: 옵션 오류 또는 예약 불가 노출 후 다른 객실 선택 여부

## 8. 분석 시 주의사항

- 실제 호텔 운영 상태, 실제 평점 또는 실제 객실 재고를 나타내지 않는다.
- 세션 배정은 무작위 표본 추출이 아니라 세션 ID 기반 결정적 배정이다.
- 사용자 표본의 연령·여행 빈도·목적 구성이 결과에 영향을 줄 수 있다.
- 오류 조건은 연구 목적의 시뮬레이션이므로 Agoda의 실제 품질 수준으로 해석하면 안 된다.
- 결과 보고 시 정상군과 오류군의 표본 수, 신뢰구간, 날짜·인원·선택 옵션 분포를 함께 제시해야 한다.

## 10. 결론

StayTrace는 실제 예약 사이트와 유사한 탐색 구조 안에서 낮은 빈도의 검색·객실 조건 불일치를 통제해 사용자 행동 변화를 측정하도록 설계됐다. 이번 비율 조정은 공개적으로 검증할 수 없는 수치를 Agoda 실제 오류율로 주장하지 않으면서도, 실제 OTA에서 발생 가능한 시설 정보와 재고 동기화 문제를 연구 가능한 수준으로 재현하는 데 목적이 있다.

## 11. 제작 및 인수인계 자료

사이트를 재구축하거나 수정하는 데 필요한 제품 명세, Codex 통합 프롬프트와 유지보수 프롬프트, 코드 지도, 데이터·이벤트·실험 설계, 설치·테스트·배포 절차, 운영·보안 원칙, 요구사항 변천과 배포 체크리스트는 `staytrace-site-production-kit.zip`으로 함께 제공한다. 비밀 API 키와 단기 배포 자격 증명은 포함하지 않는다.

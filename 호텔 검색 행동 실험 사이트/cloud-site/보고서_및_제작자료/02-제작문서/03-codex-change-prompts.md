# Codex 유지보수 프롬프트 모음

아래 문장은 필요한 항목만 복사해 사용할 수 있다.

## 기능 수정

```text
현재 StayTrace 프로젝트의 기존 기능과 공개 URL을 유지하면서 [수정할 기능]을 구현해줘. 먼저 관련 소스와 DB 구조를 확인하고, 이벤트 수집 기준이 바뀌는지도 검토해. 수정 후 프로덕션 빌드와 핵심 사용자 흐름을 검증하고 같은 Sites 프로젝트에 배포해줘. 비밀 키는 출력하거나 파일에 저장하지 마.
```

## 검색 옵션 추가

```text
검색 상세 옵션에 [옵션명]을 추가해줘. UI, 검색 조건 저장, SEARCH_FILTER CSV, 호텔 필터링, 객실 불일치 실험 대상, option_mismatch_exposure 이벤트를 모두 함께 반영해. 옵션 변경만으로는 이벤트를 만들지 말고 적용 버튼을 눌렀을 때 저장해.
```

## 호텔 데이터 보충

```text
[도시/세부지역] 호텔 데이터를 보충해줘. 중복 호텔 ID와 이름을 검사하고, 총 개수·세부지역 분포·호텔별 리뷰 5개·객실 3종을 기존 형식과 동일하게 유지해. 공개 사실과 시뮬레이션 값을 구분하고 실제 평점·가격이라고 단정하지 마. 생성 후 데이터 개수 검증 결과를 알려줘.
```

## 이벤트 감사

```text
현재 EVENT 수집을 감사해줘. 검색 제출, 노출 순위, 호텔 클릭, 상세 진입, 뒤로가기, 갤러리, 찜, 객실 선택, 예약 시작·취소·완료, 키워드 오류, 옵션 불일치가 user_id/session_id/search_id/hotel_id와 함께 시간순으로 복원되는지 확인해. 진단만 하지 말고 누락을 수정하고 빌드·배포해줘.
```

## 오류 비율 변경

```text
오류 실험의 정상군/처리군 비율을 [값]으로, 처리군 내 객실 옵션 불일치를 [값]으로, 키워드 불일치를 [값]으로 변경해줘. 전체 기대 발생률을 계산하고 코드·이벤트 속성·보고서 수치를 동시에 수정해. Agoda 실측값이라는 표현은 사용하지 말고 결정적 해시 재현성을 유지해.
```

## 관리자 데이터 개선

```text
관리자 콘솔에 [기능]을 추가해줘. 기존 테이블 CSV, 소프트 삭제와 복구를 손상시키지 말고 사용자 행동 데이터와 관리자 조작 이벤트를 구분해. 모바일 표 탐색도 확인하고 배포해줘.
```

## 버그 수정

```text
[재현 단계]에서 [오류 현상]이 발생해. 관련 상태 전환과 API 응답을 조사해 원인을 특정하고 수정해줘. 특히 session_id와 search_id가 끊기거나 중복 이벤트가 생기지 않는지 확인해. 수정 전후 재현 결과와 배포 URL을 알려줘.
```

## 문서 동기화

```text
현재 코드와 docs/site-production-kit 문서를 비교해 달라진 기능, 데이터 컬럼, 이벤트, 실행·배포 절차를 문서에 동기화해줘. 비밀정보와 단기 토큰은 제외하고, 빌드 후 기존 공개 사이트에 반영해줘.
```

## 배포만 수행

```text
현재 변경사항을 검토하고 프로덕션 빌드가 성공하면 기존 .openai/hosting.json의 Sites 프로젝트를 재사용해 배포해줘. 새 사이트나 새 URL을 만들지 말고, 배포 후 사용자 페이지와 보고서 URL의 응답을 확인해줘.
```

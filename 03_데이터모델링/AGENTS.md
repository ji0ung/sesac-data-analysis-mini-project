# Data analysis guardrails

이 폴더의 현재 기준 파일은 `2026-09-03_v03` 비식별 분석 데이터다.
원천값은 `이전버전/데이터셋/2026-09-03_v02/`에 보존되어 있으므로 임의 수정하지 않는다.

분석을 시작하기 전에 반드시 `데이터품질/호텔검색_데이터품질갱신안내_20260903_v01_현행본.md`와
`데이터품질/data_quality_manifest.json`,
`데이터품질/호텔검색_AI데이터분석지침_20260903_v01_현행본.md`를 읽고
아래 품질 플래그를 적용한다.

## 필수 규칙

1. `search_2026-09-03_v03_비식별.csv`와 SQLite `search` 테이블에는
   `invalid_stay_date_flag`가 직접 포함되어 있다. 별도 플래그 조인은 필요 없다.
2. 숙박일수, 체크아웃 날짜, 숙박기간 및 숙박 날짜 코호트처럼 숙박 날짜의 유효성을
   전제로 하는 지표는 `invalid_stay_date_flag = 0`만 사용한다.
3. 검색 시각 기반 행동 분석에서는 숙박일 역전 검색을 행 전체에서 삭제하지 않는다.
   체크인만 사용하는 리드타임은 체크아웃이 계산에 필요 없다는 계약이 명시된 경우에만
   유지할 수 있으며, 기본값은 제외다.
4. `event_2026-09-03_v03_비식별.csv`와 SQLite `event` 테이블에는
   `click_in_result_flag`가 직접 포함되어 있다. `hotel_click`은 반드시 이 컬럼을 확인한다.
5. 노출을 전제로 하는 클릭률, 노출-클릭 퍼널, 검색결과 호텔 귀속 분석은
   `click_in_result_flag = 1`만 사용한다.
6. 전체 검색의 클릭/상세진입 존재 여부처럼 순수 행동 분석에서는
   `click_in_result_flag = 0` 이벤트도 유지하되, 노출 연결이 검증되지 않았음을 명시한다.
7. `click_in_result_flag`의 NULL은 `hotel_click`이 아닌 이벤트에서만 정상이며
   "적용 대상 아님"을 뜻한다. `hotel_click`인데 NULL이면 분석을 중단한다.
   `invalid_stay_date_flag`는 모든 `search` 행에서 0 또는 1이어야 한다.
8. 재현 가능한 SQL이 필요하면 `데이터품질/analysis_guardrails.sql`의 TEMP VIEW를 사용한다.

현재 기준 데이터는 `2026-09-03_v03`이며, 알려진 이슈는 숙박일 역전 9건과
검색결과에 없는 호텔 클릭 2건이다. 원천 확인 전 날짜나 이벤트 키를 추정 보정하지 않는다.
이 행들을 데이터셋 전체에서 제외하거나 삭제하지 말고, 위 규칙에 따라 관련 지표에서만
조건부 처리한다.

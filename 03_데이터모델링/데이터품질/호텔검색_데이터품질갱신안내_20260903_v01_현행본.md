# 호텔 검색 데이터 품질 갱신 안내

## 1. 현재 기준 파일

2026-09-03 v03 비식별 스냅샷이 현재 분석 기준이다. 파일명에
`_2026-09-03_v03_비식별`이 포함된 CSV 8개와 SQLite 1개를 사용한다.
v02는 원천 보존본이며 `03_데이터모델링/이전버전/데이터셋/2026-09-03_v02/`에 있다.

## 2. 무엇이 바뀌었나

- `search`에 `invalid_stay_date_flag` 컬럼을 추가했다.
- `event`에 `click_in_result_flag` 컬럼을 추가했다.
- 별도 플래그 파일을 조인할 필요가 없도록 CSV와 SQLite 테이블에 직접 반영했다.
- 원천값과 행 수는 유지했다. 날짜나 이벤트 키를 추정 수정하지 않았다.

| 품질 문제 | 플래그 | 대상 | 관련 지표 처리 | 행동 데이터 처리 |
|---|---|---:|---|---|
| 체크아웃이 체크인보다 빠름 | `invalid_stay_date_flag=1` | 검색 9건 | 숙박 날짜 기반 지표에서 제외 | 결과 없음·재검색·클릭 분석에는 유지 |
| 클릭 호텔이 검색결과에 없음 | `click_in_result_flag=0` | 클릭 2건 | 노출 기반 전환율에서 제외 | 클릭·상세진입 존재 및 이벤트 흐름에는 유지 |

## 3. 바로 확인하는 방법

```sql
SELECT search_id, checkin_date, checkout_date
FROM search
WHERE invalid_stay_date_flag = 1;

SELECT event_id, search_id, hotel_id, event_at
FROM event
WHERE event_type = 'hotel_click'
  AND click_in_result_flag = 0;
```

CSV에서는 같은 컬럼을 각각 1과 0으로 필터링한다. `event.click_in_result_flag`의 공란은
`hotel_click`이 아닌 이벤트에 대한 "적용 대상 아님"이며 오류가 아니다.

## 4. 사용 시 주의

- v02 파일을 현재 분석에 사용하지 않는다.
- 검색 또는 이벤트 행 전체를 일괄 삭제하지 않는다.
- 지표가 어떤 플래그를 적용했는지 결과물의 방법론 또는 주석에 적는다.
- 원천 확인 전 날짜 교환, 숙박일수 절댓값 처리, 클릭 키 보정을 하지 않는다.
- 상세 정의는 `data_quality/data_quality_manifest.json`을 기준으로 한다.
- AI 분석에는 `호텔검색_AI데이터분석지침_20260903_v01_현행본.md`를 함께 적용한다.

## 5. 팀 공유용 안내 문장

> 분석 데이터가 2026-09-03 v03으로 갱신되었습니다. 앞으로는 `03_데이터모델링/현행데이터/`의 v03 비식별 CSV 또는 SQLite를 사용해 주세요. `search`에는 `invalid_stay_date_flag`, `event`에는 `click_in_result_flag`가 직접 추가되어 있습니다. 숙박 날짜 기반 지표는 전자가 0인 검색만, 노출 기반 클릭·전환 지표는 `hotel_click` 중 후자가 1인 이벤트만 사용하되, 결과 없음·재검색·클릭·상세진입 같은 행동 분석에서는 해당 행을 삭제하지 않습니다. 기존 v02는 원천 보존용이므로 현재 분석에는 사용하지 않습니다.

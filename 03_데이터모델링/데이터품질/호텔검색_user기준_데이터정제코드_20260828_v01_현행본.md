# 2026-08-28 18:00 이후 USER 기준 데이터 정제 코드

## 1. 정제 개요

- 기준 시각: `2026-08-28 18:00:00 KST`
- 기준 테이블: `user`
- 사용자 선정 조건: `signup_at >= 2026-08-28 18:00:00`
- 처리 방식: 기준을 충족하는 `user_id`를 먼저 선정한 다음, 해당 사용자와 연결된 이벤트·검색·예약 데이터를 관계 및 시간 조건에 따라 필터링
- 사용 언어: PowerShell
- 실제 실행 코드: `.artifact_work/process_valid_data.ps1`
- 검증 코드: `.artifact_work/validate_filtered_data.ps1`

> `-ge` 연산자를 사용했으므로 18시 정각을 포함한다. 즉, “18시 초과”가 아니라 “18시 이상” 조건이다.

## 2. 입출력 데이터

### 입력 CSV

당시 코드는 SQLite 데이터베이스를 직접 조회하지 않고, 데이터베이스에서 추출된 다음 CSV 파일을 읽어 처리했다.

| 테이블 | 입력 파일 |
|---|---|
| USER | `user_2026-09-01.csv` |
| EVENT | `event_2026-09-01.csv` |
| SEARCH | `search_2026-09-01.csv` |
| SEARCH_RESULT | `search_result_2026-09-01.csv` |
| SEARCH_FILTER | `search_filter_2026-09-01.csv` |
| BOOKING | `booking_2026-09-01.csv` |

입력 경로는 당시 다음과 같이 지정했다.

```powershell
$sourceDir = 'C:\Users\ENCO\Downloads'
```

### 출력 경로

```powershell
$outputDir = 'C:\Users\ENCO\Documents\mission1\team_i\processed_after_2026-08-28_1800_KST'
```

## 3. 테이블별 정제 계약

| 테이블 | 정제 조건 |
|---|---|
| `user` | `signup_at >= 2026-08-28 18:00:00 KST` |
| `event` | 정제 대상 `user_id`이면서 `event_at >= 해당 사용자의 signup_at` |
| `search` | 세션 소유자가 정확히 한 명이고, 그 소유자가 정제 대상 사용자이며 `search_time >= signup_at` |
| `search_result` | 정제 후 남은 `search_id`에 연결된 행만 유지 |
| `search_filter` | 정제 후 남은 `search_id`에 연결된 행만 유지 |
| `booking` | 정제 대상 `user_id`, `booking_at >= signup_at`, `booking_status = 'confirmed'` |
| `hotel` | 필터링하지 않고 전체 마스터 유지 |
| `room` | 필터링하지 않고 전체 마스터 유지 |

## 4. 전체 정제 코드

```powershell
$ErrorActionPreference = 'Stop'

$sourceDir = 'C:\Users\ENCO\Downloads'
$outputDir = 'C:\Users\ENCO\Documents\mission1\team_i\processed_after_2026-08-28_1800_KST'
$boundary = [datetime]'2026-08-28 18:00:00'

if (Test-Path -LiteralPath $outputDir) {
    throw "Output directory already exists: $outputDir"
}
New-Item -ItemType Directory -Path $outputDir | Out-Null

function Read-Table([string]$name) {
    Import-Csv -LiteralPath (Join-Path $sourceDir $name)
}

function Parse-Kst([string]$value) {
    if ([string]::IsNullOrWhiteSpace($value)) { return $null }
    $clean = $value -replace ' KST$', ''
    [datetime]::ParseExact(
        $clean,
        'yyyy-MM-dd HH:mm:ss',
        [Globalization.CultureInfo]::InvariantCulture,
        [Globalization.DateTimeStyles]::None
    )
}

function Write-Table([object[]]$rows, [string]$name) {
    $path = Join-Path $outputDir $name
    $rows | Export-Csv -LiteralPath $path -NoTypeInformation -Encoding UTF8
}

$users = Read-Table 'user_2026-09-01.csv'
$events = Read-Table 'event_2026-09-01.csv'
$searches = Read-Table 'search_2026-09-01.csv'
$results = Read-Table 'search_result_2026-09-01.csv'
$filters = Read-Table 'search_filter_2026-09-01.csv'
$bookings = Read-Table 'booking_2026-09-01.csv'

# 사용자 ID를 키로 사용자 정보를 빠르게 조회하기 위한 사전
$userById = @{}
foreach ($row in $users) {
    $userById[$row.user_id] = $row
}

# 기준 시각 이후 가입 사용자 선정
$validUsers = @(
    $users | Where-Object {
        (Parse-Kst $_.signup_at) -ge $boundary
    }
)

$validUserIds = [Collections.Generic.HashSet[string]]::new()
foreach ($row in $validUsers) {
    [void]$validUserIds.Add($row.user_id)
}

# 정제 대상 사용자의 가입 이후 이벤트만 유지
$validEvents = @(
    $events | Where-Object {
        $validUserIds.Contains($_.user_id) -and
        (Parse-Kst $_.event_at) -ge
            (Parse-Kst $userById[$_.user_id].signup_at)
    }
)

# 전체 이벤트에서 session_id별 user_id 집합 생성
$sessionUsers = @{}
foreach ($row in $events) {
    if (
        [string]::IsNullOrWhiteSpace($row.session_id) -or
        [string]::IsNullOrWhiteSpace($row.user_id)
    ) {
        continue
    }

    if (-not $sessionUsers.ContainsKey($row.session_id)) {
        $sessionUsers[$row.session_id] =
            [Collections.Generic.HashSet[string]]::new()
    }

    [void]$sessionUsers[$row.session_id].Add($row.user_id)
}

# 세션과 사용자의 관계 및 검색 시각을 이용해 검색 데이터 정제
$validSearches = [Collections.Generic.List[object]]::new()
$validSearchIds = [Collections.Generic.HashSet[string]]::new()

foreach ($row in $searches) {
    # 이벤트에 존재하지 않는 세션 제외
    if (-not $sessionUsers.ContainsKey($row.session_id)) {
        continue
    }

    # 한 세션이 여러 사용자에게 연결된 경우 제외
    $owners = @($sessionUsers[$row.session_id])
    if ($owners.Count -ne 1) {
        continue
    }

    $owner = $owners[0]

    # 정제 대상 사용자가 아닌 경우 제외
    if (-not $validUserIds.Contains($owner)) {
        continue
    }

    # 가입 전에 발생한 검색 제외
    if (
        (Parse-Kst $row.search_time) -lt
        (Parse-Kst $userById[$owner].signup_at)
    ) {
        continue
    }

    $validSearches.Add($row)
    [void]$validSearchIds.Add($row.search_id)
}

# 살아남은 검색에 연결된 결과 및 필터만 유지
$validResults = @(
    $results | Where-Object {
        $validSearchIds.Contains($_.search_id)
    }
)

$validFilters = @(
    $filters | Where-Object {
        $validSearchIds.Contains($_.search_id)
    }
)

# 정제 대상 사용자의 가입 이후 확정 예약만 유지
$validBookings = @(
    $bookings | Where-Object {
        $validUserIds.Contains($_.user_id) -and
        (Parse-Kst $_.booking_at) -ge
            (Parse-Kst $userById[$_.user_id].signup_at) -and
        $_.booking_status -eq 'confirmed'
    }
)

Write-Table $validSearches.ToArray() 'search_2026-09-01_filtered.csv'
Write-Table $validResults 'search_result_2026-09-01_filtered.csv'
Write-Table $validBookings 'booking_2026-09-01_filtered.csv'
Write-Table $validFilters 'search_filter_2026-09-01_filtered.csv'
Write-Table $validUsers 'user_2026-09-01_filtered.csv'
Write-Table $validEvents 'event_2026-09-01_filtered.csv'

$summary = [ordered]@{
    output_dir   = $outputDir
    boundary_kst = $boundary.ToString('yyyy-MM-dd HH:mm:ss')
    search       = $validSearches.Count
    search_result = $validResults.Count
    booking      = $validBookings.Count
    search_filter = $validFilters.Count
    user         = $validUsers.Count
    event        = $validEvents.Count
}

[pscustomobject]$summary | ConvertTo-Json
```

## 6. 검증 항목

별도 검증 스크립트에서 다음 항목을 확인했다.

1. 각 테이블의 실제 행 수와 예상 행 수 일치 여부
2. 테이블별 기본키 중복 건수
3. 입력 CSV와 출력 CSV의 컬럼 구조 일치 여부
4. 기준 시각 이전 가입 사용자의 잔존 여부
5. 가입 전 이벤트의 잔존 여부
6. 가입 전 예약의 잔존 여부
7. 정제 사용자에 연결되지 않은 이벤트·예약 존재 여부
8. `confirmed`가 아닌 예약의 잔존 여부
9. 부모 검색이 없는 `search_result` 및 `search_filter` 존재 여부

검증 기준 코드는 다음과 같다.

```powershell
$relationshipChecks = [ordered]@{
    users_before_boundary = @(
        $tables.user | Where-Object {
            (Parse-Kst $_.signup_at) -lt $boundary
        }
    ).Count

    events_missing_user = @(
        $tables.event | Where-Object {
            -not $validUserIds.Contains($_.user_id)
        }
    ).Count

    events_before_signup = @(
        $tables.event | Where-Object {
            (Parse-Kst $_.event_at) -lt
                (Parse-Kst $userById[$_.user_id].signup_at)
        }
    ).Count

    bookings_missing_user = @(
        $tables.booking | Where-Object {
            -not $validUserIds.Contains($_.user_id)
        }
    ).Count

    bookings_before_signup = @(
        $tables.booking | Where-Object {
            (Parse-Kst $_.booking_at) -lt
                (Parse-Kst $userById[$_.user_id].signup_at)
        }
    ).Count

    bookings_not_confirmed = @(
        $tables.booking | Where-Object {
            $_.booking_status -ne 'confirmed'
        }
    ).Count

    orphan_search_results = @(
        $tables.search_result | Where-Object {
            -not $validSearchIds.Contains($_.search_id)
        }
    ).Count

    orphan_search_filters = @(
        $tables.search_filter | Where-Object {
            -not $validSearchIds.Contains($_.search_id)
        }
    ).Count
}
```

## 7. 정제 시 주의사항

- 이 코드는 SQLite에 직접 SQL을 실행하지 않고 CSV 추출본을 처리한다.
- 날짜 문자열 끝의 ` KST`를 제거한 뒤 `yyyy-MM-dd HH:mm:ss` 형식으로 파싱한다.
- 시각이 비어 있으면 `Parse-Kst`가 `$null`을 반환하며, 별도의 결측값 대체는 수행하지 않는다.
- `session_id` 또는 `user_id`가 비어 있는 이벤트는 세션 소유자 계산에서 제외한다.
- 세션에 사용자가 없거나 두 명 이상 연결된 검색은 제외한다.
- 기본키 중복은 정제 단계에서 자동 제거하지 않고 검증 단계에서 건수만 확인한다.
- 원본 컬럼은 변경하거나 새로 계산하지 않고 그대로 출력한다.
- 현재 분석 기준 데이터는 이후 비식별화와 품질 플래그가 추가된 `2026-09-03 v03`이다. 이 문서는 최초 `2026-09-01 v01` 정제 로직을 기록한 것이다.

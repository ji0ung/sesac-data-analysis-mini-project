## 5. 로컬에서 수정하고 확인하는 방법

현재 웹앱은 `cloud-site/`에서 작업한다.

```powershell
cd cloud-site
npm install
npm run dev
```

접속 주소는 실행 후 터미널에 표시되는 `Local URL`을 사용한다. 수정한 내용은 로컬 화면에서 확인한 뒤 다음 명령으로 검증한다.

```powershell
npm run build
npm test
```

초기 Python 프로토타입을 확인할 때만 루트에서 `python run.py`를 실행하며, 기본 주소는 다음과 같다.

- 사용자 화면: http://127.0.0.1:8000
- 관리자 화면: http://127.0.0.1:8000/admin

초기 프로토타입은 현재 운영 사이트의 배포 대상이 아니다.

## 6. 수정 후 배포 흐름

1. `cloud-site/`의 필요한 코드를 수정한다.
2. 기능과 관련된 제작 문서·공개 보고서를 함께 갱신한다.
3. 의존성을 설치하고 빌드 및 테스트를 통과시킨다.
4. 기존 `cloud-site/.openai/hosting.json`의 Sites 프로젝트를 재사용한다.
5. 새 버전을 저장하고 기존 운영 사이트에 배포한다.
6. 운영 주소, 공개 보고서, 공개 제작자료 주소가 정상 응답하는지 확인한다.

배포 세부 체크리스트는 `cloud-site/docs/site-production-kit/09-release-checklist.md`를 따른다.

## 7. 수정 요청을 작성하는 방법

Codex에서 수정할 때는 다음 형식으로 요청하면 범위가 분명해진다.

```text
호텔 프로젝트의 cloud-site를 수정해줘.
변경 내용: [원하는 기능 또는 디자인]
함께 갱신할 문서: [보고서/데이터 명세/운영 문서]
검증: 빌드와 테스트
배포: 기존 StayTrace Sites 프로젝트와 기존 URL 재사용
```

기존 주소를 유지해야 한다면 항상 “새 사이트를 만들지 말고 기존 `.openai/hosting.json`의 프로젝트를 재사용”한다고 명시한다.

## 8. 비밀정보와 운영 주의사항

날짜·시간 기록은 `Asia/Seoul`을 기준으로 하며, 저장값은 `+09:00` 오프셋을 포함한다. 세부 규칙은 `cloud-site/docs/site-production-kit/11-korean-time-standard.md`에서 관리한다.

- `.env` 계열 파일의 값, API 키, 배포 자격 증명은 보고서나 공개 ZIP에 넣지 않는다.
- 호스팅 환경 변수는 Sites에서 관리하고 저장소 문서에는 변수 이름과 용도만 기록한다.
- `.openai/hosting.json`에는 프로젝트 연결과 논리적 D1/R2 바인딩만 둔다.
- 외부 API를 추가하면 실패·할당량·개인정보 처리 방식을 문서에 함께 기록한다.
- 사이트 접근 범위나 소유자·편집자 권한 변경은 코드 수정과 별개의 운영 변경으로 취급한다.

## 9. 수정 전 확인 순서

1. 이 문서에서 수정 대상 파일을 찾는다.
2. `호텔_프로젝트_종합보고서.md`에서 의도와 범위를 확인한다.
3. `cloud-site/docs/site-production-kit/01-product-spec.md`에서 현재 제품 규칙을 확인한다.
4. 데이터 변경이면 데이터 명세와 DB migration을 확인한다.
5. 수정 후 릴리스 체크리스트로 배포 여부를 판단한다.

# 운영, 데이터 관리와 보안

## 1. 공개 범위

사이트는 링크를 아는 누구나 접근할 수 있는 공개 연구 사이트다. 관리자 화면도 현재 같은 앱 안에 있으므로 실제 개인정보, 비공개 연구 데이터 또는 운영 비밀을 넣어서는 안 된다. 민감한 실제 연구를 시작하기 전에는 관리자 인증과 역할 기반 접근 제어를 별도로 도입해야 한다.

## 2. 개인정보 최소화

- 이름은 연구용 별명 사용을 안내한다.
- 전화번호, 이메일, 주소를 요구하지 않는다.
- 성별·연령대 등 연구에 필요하지 않은 항목은 수집 목적을 재검토한다.
- 참여자에게 수집 항목, 이용 목적, 보관 기간, 삭제 요청 방법을 고지한다.
- 같은 이름을 같은 사용자로 처리하므로 동명이인을 구분하지 못한다는 한계가 있다.

## 3. API 키

- 키는 Sites의 서버 런타임 환경변수에 저장한다.
- `NEXT_PUBLIC_` 접두어를 사용하면 브라우저에 공개될 수 있으므로 서버 전용 키에 사용하지 않는다.
- `.env`는 로컬 전용이며 Git에 커밋하지 않는다.
- 문서, 스크린샷, 오류 메시지, CSV에 키를 넣지 않는다.
- 키가 노출되면 즉시 공급자 콘솔에서 폐기·재발급한다.

## 4. 호텔 이미지와 외부 데이터

- 실제 호텔 사진을 사용할 때는 API 약관, 저장 허용 여부, 재배포 권리와 출처 표시를 확인한다.
- 사진 URL을 무단 수집하거나 영구 복제하지 않는다.
- API 제공자가 허용하지 않으면 생성 이미지 또는 명시적으로 사용 허가된 이미지를 사용한다.
- 실제 호텔명과 시뮬레이션 평점·리뷰·재고가 함께 보일 때 오인을 막는 안내문을 유지한다.

## 5. 삭제와 복구

관리자 삭제는 즉시 영구 삭제하지 않고 휴지통에 보존하는 소프트 삭제가 기본이다. 복구 시 원래 테이블과 행 ID를 검증한다. 영구 삭제 기능을 추가한다면 대상을 명확히 표시하고 별도 확인을 요구하며, 백업과 연구 데이터 보존 정책을 먼저 정한다.

## 6. 백업

- 연구 시작 전 HOTEL/REVIEW 기준 데이터 CSV 보관
- 조사 회차별 USER/SEARCH/EVENT/BOOKING CSV 스냅샷
- 배포 버전 번호와 조사 기간 기록
- 오류 실험 비율과 코드 커밋을 분석 데이터와 함께 기록
- 백업 파일은 공개 사이트 저장소 밖의 접근 제한 저장소에 보관

## 7. 모니터링

- 사이트 응답 여부
- API 오류율
- D1 쓰기 실패
- 검색 제출 대비 impression 누락
- 예약 완료 대비 reservation 레코드 누락
- 비정상적으로 높은 동일 이벤트 중복
- 처리군 실제 배정 비율과 옵션별 관측 오류율

## 8. 연구 시작 전 필수 결정

- 연구윤리 또는 기관 승인 필요 여부
- 참여 동의 문구
- 데이터 보관 기간
- 관리자 접근 통제
- 참가자 보상과 중복 참여 기준
- 실제 사용자에게 실험 오류를 고지·사후 설명하는 방식

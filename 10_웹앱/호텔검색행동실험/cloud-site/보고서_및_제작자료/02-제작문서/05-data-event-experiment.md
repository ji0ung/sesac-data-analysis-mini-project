# 데이터, 이벤트와 오류 실험

## 1. 핵심 데이터 관계

```text
USER 1 ─ N SESSION 1 ─ N SEARCH 1 ─ 1 SEARCH_FILTER
                         │  │
                         │  └─ N EVENT (hotel_impression 포함)
                         └──── N RESERVATION
HOTEL 1 ─ N REVIEW
HOTEL 1 ─ N ROOM_INVENTORY
HOTEL 1 ─ N EVENT / RESERVATION
```

실제 서버가 제공하는 관리자 데이터셋 명칭은 `HOTEL`, `ROOM`, `SEARCH`, `SEARCH_FILTER`, `USER`, `EVENT`, `SEARCH_RESULT`, `BOOKING`이다. 호텔과 객실을 분리하며 각각 `hotel_id`, `room_id`를 기본키로 사용한다. 리뷰 작성 값은 별도 리뷰 테이블이 아니라 EVENT의 별점·리뷰 완료 시각·리뷰 텍스트 칼럼으로 수집한다.

## 2. 식별자 규칙

- 새로 생성되는 ID는 표 종류를 나타내는 영문 1자와 영숫자 9자로 구성해 총 10자로 유지한다. 예: 사용자 `U…`, 세션 `S…`, 검색 `Q…`, 이벤트 `E…`, 예약 `B…`.
- 난수 부분은 대소문자와 숫자를 조합해 짧은 길이에서도 충분한 유일성 공간을 확보한다. DB의 기본키 제약이 중복 저장을 한 번 더 방지한다.
- 기존에 저장된 긴 ID는 PK/FK 관계 보존을 위해 변경하지 않으며 새 레코드부터 짧은 형식을 사용한다.
- 동일한 정규화 이름은 동일 `user_id`
- 한 탭 안의 탐색은 동일 `session_id`
- 검색·필터 적용 버튼을 누를 때마다 새 `search_id`
- 재검색은 직전 검색을 `parent_id`로 연결
- 예약은 이를 발생시킨 `search_id`와 `hotel_id`를 보유
- 이벤트 시간은 ISO datetime으로 저장하고 시간순 정렬 가능

## 3. 주요 이벤트 사전

| 이벤트 | 발생 시점 | 주요 속성 |
|---|---|---|
| `session_start` | 참여 시작 | 사용자 정보, 실험군 |
| `search_submit` | 검색/옵션 적용 버튼 | 조건, 결과 수, submit_trigger |
| `hotel_impression` | 결과 호텔 노출 | rank, hotel_id |
| `keyword_search_result` | 정상 키워드 결과 | 키워드, 정규화 단어, 결과 수 |
| `keyword_search_error_exposure` | 누락·비관련 결과 노출 | omitted/injected IDs, 비율 |
| `hotel_click` | 호텔 카드 선택 | 호텔, 검색 문맥 |
| `hotel_detail_view` | 상세 진입 | 호텔, 검색 문맥 |
| `back_to_results` | 결과로 복귀 | 이전 페이지, 호텔 |
| `hotel_gallery_view` | 화살표/썸네일 이미지 선택 | image_index, method |
| `wishlist_add/remove` | 찜 상태 변경 | hotel_id |
| `option_mismatch_exposure` | 요청 옵션과 객실 불일치 | requested/mismatch options, 비율 |
| `room_select` | 판매 가능한 객실 선택 | 객실명, 가격, 날짜 |
| `booking_start` | 예약 확인 진입 | 호텔, 객실, 금액 |
| `booking_cancel` | 예약 취소 | 복귀 대상, 단계 |
| `booking_complete` | 모의 예약 확정 | 예약 ID, 금액 |

이벤트명은 코드가 최종 정본이다. 새 이벤트를 추가하면 이 표와 관리자 CSV를 함께 갱신한다.

## 4. 오류 실험 배정

현재 보정값:

| 항목 | 조건부 비율 | 전체 기대 발생률 |
|---|---:|---:|
| 오류 실험 세션 | 전체의 25% | 25% |
| 선택 객실 옵션 불일치 | 오류군의 옵션별 32% | 옵션당 약 8% |
| 키워드 결과 불일치 | 오류군의 검색별 20% | 검색당 약 5% |

계산은 `전체 발생률 = 오류군 비율 × 오류군 내 발생률`이다. 따라서 `0.25 × 0.32 = 0.08`, `0.25 × 0.20 = 0.05`다.

배정은 세션 ID 문자값을 이용한 결정적 해시다. 무작위처럼 분산되지만 동일한 세션·호텔·옵션 조합은 재실행해도 같은 결과를 내므로 연구 재현성이 유지된다.

## 5. 오류 유형

- 객실 옵션 불일치: 호텔 시설에는 조건이 보이나 남은 객실 상품에는 선택 옵션이 없음
- 키워드 누락: 의미상 맞는 호텔 일부를 결과에서 제외
- 비관련 삽입: 올바른 결과와 다른 호텔 일부를 결과에 포함
- 정상 재고 부족: 2026년 날짜·호텔·객실 조합의 판매 마감. 실험 오류로 집계하지 않음

## 6. 해석 한계

Agoda는 전체 검색·필터 오류율을 공개하지 않는다. 이 비율은 Agoda 공식 실측값이 아니며 공개 파트너 문서의 시설 정보 표시 문제와 채널별 재고 차이를 참고한 연구 설계값이다. 연구 결과를 Agoda의 서비스 품질 평가로 해석해서는 안 된다.

## 7. 분석 지표

- 세션당 검색 수와 재검색률
- 검색 결과 0건 비율
- 호텔별 노출 수, 평균 순위, 카드 클릭률
- 검색→상세, 상세→객실, 객실→예약 시작, 예약 시작→완료 전환율
- 정상군과 오류군의 재검색·이탈·예약 차이
- 옵션별 불일치 후 대체 객실 선택률
- 키워드 오류 후 검색어 변경률

분석 시 군별 표본 수, 날짜·인원·옵션 분포, 신뢰구간을 함께 제시한다.

## 1. 한 줄 요약

검색결과가 0건일 때 실험군에 지역 변경 행동과 `Z→P` 회복확률 `+6%p`를 함께 적용하고, 검색 실패와 회복 관련 KPI가 어떻게 달라지는지 확인한 합성 시뮬레이션이다.

이번 결과는 지역 변경 기능의 실제 효과를 입증한 결과가 아니다. 실제 A/B 테스트 전에 가정한 데이터 흐름과 KPI 계산이 작동하는지 확인한 결과다.

## 2. 실험 대상과 배정 방식

총 10,000명의 합성 사용자를 다음과 같이 구성했다.

| 구분 | 사용자 수 | 적용 내용 |
|---|---:|---|
| 대조군(Control) | 5,000명 | 기존 검색 흐름과 상태 전환확률 유지 |
| 실험군(Treatment) | 5,000명 | 검색결과 0건 이후 지역 변경 행동과 회복확률 증가 적용 |
| 전체 | 10,000명 | 동일한 사전 조건을 가진 5,000개 사용자 짝으로 구성 |

`pair_id` 하나마다 대조군 사용자 한 명과 실험군 사용자 한 명이 연결된다. 같은 짝의 두 사용자는 다음 사전 조건을 공유한다.

- 지역군
- 가격 설정 여부
- 옵션 수
- 위험 수준
- 첫 검색 상태
- 기준 세션 계보 정보

그 뒤의 검색 경로는 대조군과 실험군에 각각 따로 생성했다. 사전 속성 불일치와 실험 설정이 대조군에 들어간 사례는 모두 0건으로 검사됐다.

## 3. 검색 상태 정의

| 상태 | 뜻 |
|---|---|
| `Z` | 검색결과가 0건인 상태 |
| `P` | 검색결과가 1건 이상인 상태 |
| `END` | 검색 세션이 끝난 상태 |

두 집단 모두 첫 검색을 `Z` 또는 `P`로 시작한다. 이후 현재 검색 상태, 첫 실패 여부, 이전 실패 경험에 따라 `Z`, `P`, `END`로 이동한다. 세션은 `END`가 나오거나 검색이 최대 31회가 되면 끝난다.

## 4. 대조군 설정

대조군에는 별도의 개선 가정을 적용하지 않았다. 검색결과가 0건이어도 기존 상태 전환확률에 따라 다음 상황이 결정된다.

- 다시 검색했지만 또 0건이 나옴: `Z→Z`
- 다음 검색에서 결과를 찾음: `Z→P`
- 검색을 끝냄: `Z→END`

대조군은 채택된 1,000명 기준 DB의 검색 흐름을 재현하기 위한 비교 기준이다.

## 5. 실험군 설정

실험군에서 직전 검색결과가 0건이면 다음 두 설정을 함께 적용했다.

1. 다음 검색에서 결과가 1건 이상 나올 `Z→P` 확률에 `0.06`, 즉 6%p를 더했다.
2. 후속 행동 유형을 `region_change`로 기록했다.

```text
실험군의 Z→P 확률 = 대조군의 기존 Z→P 확률 + 0.06
```

이 설계는 사용자가 지역 변경 제안을 실제로 보고 선택하는 과정을 재현한 것이 아니다. 생성 코드가 검색결과 0건 이후의 행동을 `region_change`로 부여하고 회복확률도 함께 높인 구조다.

따라서 정확한 표현은 다음과 같다.

> 실험군은 검색결과가 0건일 때 인접 지역으로 검색 범위를 바꾸는 상황과 예상 회복효과를 함께 적용한 합성 집단이다.

다음 표현은 현재 데이터로 뒷받침할 수 없다.

> 사용자가 실제로 지역 변경 제안을 보고 이를 선택했으며, 그 선택 때문에 검색이 회복됐다.

## 6. 원래 A/B 테스트 기획

기획안의 목표는 검색결과 0건 사용자를 하나의 집단으로 보지 않고, 추정 의도에 따라 여섯 집단으로 나눈 뒤 각 집단에 맞는 제안을 제공하는 것이었다.

| 의도 세그먼트 | 사용자의 추정 의도 | 기획한 주 처치 | 관찰할 행동 |
|---|---|---|---|
| `condition_keeper` | 조건을 쉽게 포기하지 않음 | 반복 경고와 대안 비교 | 같은 조건 반복·조건 강화·완화 |
| `location_flexible` | 위치를 넓혀서라도 찾음 | 인접 지역 확대 | 지역 변경 |
| `budget_flexible` | 예산을 조정할 수 있음 | 가격 범위 확대 | 가격 완화 |
| `option_count_flexible` | 요구 옵션 수를 줄일 수 있음 | 옵션 수 줄이기 | 옵션 수 완화 |
| `query_reframer` | 검색 표현을 수정하려 함 | 연관어와 자동완성 | 검색어 변경 |
| `rapid_resolver` | 조건을 빠르게 바꿔 결과를 찾음 | 성공 가능성이 높은 제안을 차례로 제공 | 여러 조건 변경 |

기획 단계에서는 같은 의도군 안에서 대조군과 실험군을 비교하려 했다. 실험 전의 `intent_segment`는 누구에게 무엇을 보여줄지 결정하고, 실험 후의 SG1~SG4는 결과가 어떻게 끝났는지 판정하는 별도 분류로 설계했다.

### 기획한 가설

| ID | 가설 | 주 KPI | 대상 |
|---|---|---|---|
| H0 | 대조군과 실험군의 성과 차이가 없다. | 결과 회복률 | 전체 |
| H1 | 의도에 맞는 제안은 전체 결과 회복률을 높인다. | 회복률 차이 | 전체 |
| H2 | 개선 효과의 크기는 의도 세그먼트에 따라 다르다. | 세그먼트와 처치의 상호작용 | 6개 의도군 |
| H3 | 검색결과 회복은 호텔 상세진입 증가로 이어진다. | 회복 후 상세진입률 | 전체 |
| H4 | 반복 방지 안내는 같은 조건의 반복 검색을 줄인다. | 동일 조건 반복률 | `condition_keeper` |
| H5 | 지역 확대는 위치 유연형의 회복에 특히 효과적이다. | 회복률 | `location_flexible` |
| H6 | 검색어 제안은 표현 수정형의 상세진입률을 높인다. | 상세진입률 | `query_reframer` |

## 7. 전환확률 `+6%p`의 근거

`+6%p`는 실제 사용자 데이터에서 계산한 효과값이 아니다. 또한 실제 실험에서 얻은 추정값이나 95% 신뢰구간도 아니다.

기획안은 효과 크기의 시작 범위를 다음과 같이 제시했다.

| 기획 시나리오 | 효과 크기의 시작 범위 |
|---|---:|
| 보수적 | +2~3%p |
| 기준 | +5~8%p |
| 낙관적 | +10~15%p |

기획안은 `+5~8%p`를 기준 시나리오의 시작 범위로 두었으며, 이 수치 역시 실제 성과가 아닌 시뮬레이션 가정이라고 명시했다. 최종 생성 설정은 이 범위 안의 `+6%p`를 expected 값으로 채택하고, 비교용 시나리오를 `+3%p·+6%p·+9%p`로 구체화했다.

세 가지 시나리오를 다음과 같이 정하고 그중 중간값을 expected 시나리오로 선택했다.

| 시나리오 | `Z→P` 확률 증가 |
|---|---:|
| 보수적(Conservative) | +3%p |
| 예상(Expected) | +6%p |
| 낙관적(Optimistic) | +9%p |

10,000명 DB에는 expected 시나리오 한 번만 적용했다. 기존 분석의 `treatment_posteriors`와 `search_hazard`도 최종 `+6%p` 설정에 직접 사용되지 않았다.

확인 가능한 근거는 다음처럼 구분해야 한다.

| 구분 | 판단 |
|---|---|
| 0건 이후 조건 완화를 검토하는 방향 | 이전 분석과 교수 우선순위 문서에 근거가 있음 |
| 인접 지역 확대를 개선 후보로 선택 | 교수 우선순위의 지역 관련 개선안에 근거가 있음 |
| 기준 효과 범위를 +5~8%p로 둔 이유 | 기획 단계의 시뮬레이션 시작 가정이며 실측 성과가 아님 |
| 정확히 6%p를 적용한 이유 | 기준 범위 안에서 선택한 expected 시나리오 값이며 별도의 실측 산출 근거는 확인되지 않음 |

## 8. 원래 계획과 실제 구현의 차이

원래 계획에는 다음 개선안이 포함됐다.

- 가격 범위 확대
- 옵션 수 축소
- 인접 지역 확대
- 동일 조건 반복 방지
- 단계별 조건 완화
- 연관 검색어 제안

하지만 최종 시뮬레이션은 각 기능을 독립적으로 구현하지 않았다. 실제 핵심 처치는 `Z→P +6%p`와 0건 이후 `region_change` 기록이다.

| 항목 | 기획안 | 실제 10,000명 구현 |
|---|---|---|
| 사용자 분류 | 6개 `intent_segment` | 의도 필드 없음, `sample_stratum` 사용 |
| 실험 처치 | 의도군별 서로 다른 맞춤 제안 | 0건 이후 `region_change`와 공통 회복확률 증가 |
| 제안 과정 | 노출→선택→조건 변경→회복 | `treatment_exposed`만 있고 선택·수락 로그 없음 |
| 지역 확대 | `location_flexible`에 우선 제공 | 실험군의 0건 이후 행동에 적용 |
| 효과 해석 | 세그먼트별·기능별 효과 비교 | 섞여 있는 패키지 효과만 비교 가능 |
| 상세진입 KPI | 회복 전이 중 상세진입 | 결과가 있는 전체 검색 중 1위 상세진입 |

이 차이 때문에 기획한 H2, H4, H5, H6는 최종 DB에서 그대로 검정할 수 없다. H1의 전체 회복 방향과 H3에 가까운 전체 상세진입 변화만 제한적으로 살펴볼 수 있다. H3도 기획안의 분모와 실제 `Card H-SEARCH`의 분모가 다르므로 완전히 같은 검정은 아니다.

따라서 이번 결과는 다음을 구분하지 못한다.

- 지역 변경만의 효과
- 가격 완화만의 효과
- 옵션 축소만의 효과
- 검색어 제안만의 효과
- 사용자가 제안을 보거나 선택한 효과

이번 분석에서 확인할 수 있는 것은 여러 아이디어가 섞인 개입 패키지의 합성 결과다.

## 9. 비교한 KPI

| KPI | 계산 의미 |
|---|---|
| 검색 0건률 | 전체 검색 중 결과가 0건인 고유 검색의 비율 |
| 0건 후속검색률 | 0건 검색 중 다음 검색이 존재하는 비율 |
| 즉시 회복률 | 후속 검색이 있는 0건 검색 중 다음 결과가 1건 이상인 비율 |
| 첫 0건 즉시 회복률 | 세션의 첫 0건 이후 바로 결과를 찾은 비율 |
| 최종 회복률 | 0건을 경험한 세션 중 마지막 검색이 결과 있음으로 끝난 비율 |
| Card H-SEARCH | 결과가 있는 검색 중 1위 호텔 상세를 한 번 이상 본 고유 검색의 비율 |
| 세션당 검색 수 | 사용자 세션 한 개에서 발생한 평균 검색 횟수 |

현재 프로젝트에서 즉시 회복률을 NSM 후보로 설명할 수 있다. 다만 보고서는 실제 A/B 테스트 전에 검색 0건률과 즉시 회복률 중 하나를 주 지표로 사전 확정하도록 권장한다.

기획안의 KPI와 실제 분석 지표도 다음과 같이 구분해야 한다.

| 기획 KPI | 기획 정의 | 실제 구현 여부 |
|---|---|---|
| 결과 회복률 | 0건 후 후속 검색 중 결과가 1건 이상 나온 비율 | 즉시 회복률로 구현 |
| 조건 변경률 | 제안을 본 0건 검색 중 조건을 넓힌 후속 검색 비율 | 제안 선택·조건 변경 로그 부족으로 계산 불가 |
| 세션 최종 회복률 | 0건 경험 세션 중 마지막 검색 결과가 1건 이상인 비율 | 구현 |
| 회복 후 상세진입률 | 회복 전이 중 호텔 상세진입이 있는 비율 | 동일 정의로 미구현; 실제 분석은 전체 양수 검색 기준 `Card H-SEARCH` 사용 |

## 10. 합성 A/B 결과

| KPI | 대조군 | 실험군 | 실험군−대조군 |
|---|---:|---:|---:|
| 검색 0건률 | 49.93% | 43.59% | **-6.34%p** |
| 0건 후속검색률 | 95.07% | 95.64% | **+0.57%p** |
| 즉시 회복률 | 16.90% | 22.02% | **+5.12%p** |
| 첫 0건 즉시 회복률 | 11.42% | 15.88% | **+4.46%p** |
| 최종 회복률 | 74.20% | 80.91% | **+6.71%p** |
| Card H-SEARCH | 19.81% | 19.54% | **-0.27%p** |

합성 모형 안에서는 검색 실패가 줄고 회복 관련 지표가 높아졌다. 1위 호텔 상세진입률은 뚜렷하게 개선되지 않았다.

설정값은 `+6%p`지만 측정된 즉시 회복률 차이는 `+5.12%p`다. 검색 종료, 반복 실패, 상태 경로 길이 등 다른 생성 규칙도 함께 작동했기 때문이다.

## 11. 결과의 해석 범위

### 확인한 내용

- 같은 조건의 합성 대조군과 실험군을 짝으로 구성할 수 있었다.
- 설정한 지역 변경 행동과 회복확률 증가가 데이터에 반영됐다.
- 합성 모형 안에서 검색 0건률은 낮아지고 즉시·최종 회복률은 높아졌다.
- 회복률이 높아져도 1위 호텔 상세진입률은 거의 달라지지 않았다.

### 확인하지 못한 내용

- 실제 사용자가 지역 변경 제안을 선택하는지
- 실제 지역 변경이 검색 회복의 원인인지
- 지역 변경과 회복확률 증가 중 어느 설정이 결과를 만들었는지
- 가격, 옵션, 지역, 검색어 가운데 어떤 기능이 가장 효과적인지
- 예약과 매출이 증가하는지
- 실제 사용자에게도 같은 크기의 효과가 나타나는지

회복확률 증가를 생성 규칙에 먼저 넣었으므로, 회복률이 높아진 결과를 실제 기능의 효과 증명으로 사용할 수 없다. 이번 분석은 가정한 규칙이 제대로 작동하는지 확인한 메커니즘 점검이다.

## 12. 발표용 핵심 설명

> 합성 사용자 10,000명을 대조군과 실험군에 각각 5,000명씩 배정했습니다. 실험군에는 검색결과가 0건일 때 인접 지역으로 검색 범위를 바꾸는 상황과 예상 회복효과 6%p를 함께 적용했습니다. 그 결과 합성 모형 안에서 검색 0건률은 6.34%p 낮아지고 즉시 회복률은 5.12%p 높아졌습니다. 다만 6%p는 실제 관측값이 아닌 시나리오 가정이며, 지역 변경의 실제 효과를 입증한 결과는 아닙니다. 이번 결과는 실제 A/B 테스트 전에 지표와 데이터 흐름을 확인한 사전 시뮬레이션으로 해석했습니다.

## 13. 예상 질문과 답변

| 예상 질문 | 답변 |
|---|---|
| 사용자가 실제로 지역을 변경했는가? | 아니다. 생성 코드가 0건 이후 행동을 `region_change`로 기록했다. |
| 지역 변경이 가능한 집단인가? | 선택 가능성을 관찰한 집단이라기보다, 0건 이후 지역 변경 상황이 적용되도록 만든 합성 집단이다. |
| 변경 전후 지역을 확인할 수 있는가? | 제안 노출, 선택, 변경 전후 지역을 완전히 추적하는 전용 로그가 없어 추가 확인이 필요하다. |
| 왜 회복확률을 6%p 높였는가? | 실측값이 아니라 3%p·6%p·9%p 시나리오 중 가운데 값을 expected로 선택했다. |
| 결과를 미리 좋아지게 만든 것 아닌가? | 회복 증가를 가정에 넣었기 때문에 실제 효과 검증은 아니다. 설정한 가정이 KPI에 반영되는지 확인한 것이다. |
| 이것을 A/B 테스트라고 할 수 있는가? | 정확한 명칭은 대조군과 실험군을 구성한 합성 A/B 시뮬레이션이다. |
| 지역 변경이 회복률을 높였다고 결론 내릴 수 있는가? | 지역 변경과 회복확률 증가를 동시에 적용했으므로 지역 변경만의 효과는 알 수 없다. |
| 원래 기획한 의도별 A/B 테스트가 실행됐는가? | 아니다. 6개 의도군별 맞춤 처치는 기획 내용이고, 최종 DB에는 의도군 필드와 기능별 처치가 구현되지 않았다. |
| 6%p는 어디에서 나온 값인가? | 기획안의 기준 시나리오 시작 범위인 +5~8%p 안에서 expected 값으로 선택했다. 실제 데이터에서 추정한 효과는 아니다. |
| 10,000명이면 결과를 신뢰할 수 있는가? | 합성 표본을 늘리면 모형 안의 계산은 안정되지만, 모형의 가정이 현실과 맞는지는 해결되지 않는다. |
| 예약률도 좋아졌는가? | `BOOKING`이 0행이므로 예약 성과는 계산할 수 없다. 이는 예약률이 0%라는 뜻이 아니다. |

## 14. 실제 A/B 테스트에서 필요한 보완

실제 서비스에서는 회복확률을 코드로 높이지 않고 다음 과정 자체를 관찰해야 한다.

1. 실제 사용자를 사용자 단위로 무작위 배정한다.
2. 같은 사용자는 실험 기간에 계속 같은 집단에 둔다.
3. 대조군에는 기존 0건 화면을 보여준다.
4. 실험군에만 인접 지역 확대 제안을 보여준다.
5. 제안 노출, 클릭, 수락, 실제 지역 변경 여부를 기록한다.
6. 변경 후 다음 검색결과와 즉시 회복 여부를 기록한다.
7. 호텔 상세진입과 예약 연결을 별도로 기록한다.
8. 검색 0건률 또는 즉시 회복률 중 하나를 주 지표로 사전 확정한다.

이렇게 해야 지역 변경 제안이 실제로 회복률을 높였는지 판단할 수 있다.

## 15. 최종 판단

이번 합성 A/B 시뮬레이션은 다음 질문에 답한다.

> 검색결과 0건 이후 지역 변경과 예상 회복효과를 적용하면 합성 KPI가 어떤 방향으로 움직이는가?

이번 분석은 다음 질문에는 답하지 못한다.

> 실제 사용자에게 인접 지역 변경을 제안하면 검색 회복률이 얼마나 높아지는가?

따라서 현재 결론은 다음과 같다.

> 인접 지역 변경 제안은 실제 A/B 테스트 후보로 검토할 가치가 있다. 지역 변경의 실제 효과와 적정 효과 크기는 실제 사용자 실험에서 다시 확인해야 한다.

## 3. 프로젝트 목적과 단위

일본 여행객의 검색 의도와 실제 노출 호텔·순위·가격·무료취소·후결제 조건을 비교하고, 검색 후 행동과 이탈·재검색 원인을 진단하는 대시보드/시뮬레이션 구조를 만든다. 핵심은 검색 조건–결과 없음–후속 검색–호텔 상세진입을 연결하여 인접 지역 추천과 단계적 필터 완화 후보를 평가하는 것이다.

분모를 혼용하지 않는다: `SEARCH` 296건, 검색 세션 43개, 검색 사용자 41명, 0건 후 다음 검색 전이 140건은 서로 다른 분석 단위다.

## 6. 고정 금지사항과 분석 원칙

- 관측되지 않은 것을 관측값처럼 만들지 않는다.
- 빈 `query_text`를 오타로 단정하지 않는다. A3와 SX 실험군은 제외한다.
- B2를 인과규칙으로 사용하지 않고 0건 후 검색횟수를 강제 가산하지 않는다.
- 희소 지역×의도 셀의 우열·인과를 단정하지 않는다.
- `hotel_click`과 `hotel_detail_view`를 두 개의 성과로 더하지 않는다.
- `BOOKING` 36건은 참고 지표이며 실제 예약 성과로 확대 해석하지 않는다.
- 세션 비율에는 항상 `n=43`을 병기한다.
- 현재 `ROOM`은 물리 객실 1칸이 아니라 객실 상품/타입이다. 동일 `room_id` 예약 기간 중첩을 자동 오류로 판정하지 않는다.
- 608건과 296건은 서로 다른 DB/추출본으로만 확인되었다. 중복·추출조건 등 원인을 추정하지 않는다.
- 이 체크포인트에서 1,000명·10,000명 증강을 실행하지 않는다.

## 7. 이번 체크포인트의 결정

- 원본 DB는 수정하지 않는다.
- 스키마가 선언한 FK는 0개이므로, 관계 무결성은 분석 쿼리와 후속 파이프라인 QA로 강제한다.
- 시간은 `KST` 문자열을 `+09:00`으로 명시 변환한 후 비교한다.
- 숙박일 역전 9건은 수정 전까지 숙박일·리드타임 지표에서 제외하고 `invalid_stay_date_flag=1`로 관리한다.
- 클릭 미노출 2건과 예약–객실 호텔 불일치 2건은 원인 확인/수정 전까지 관련 전환 지표에서 제외하는 파생 플래그를 사용한다.

## 8. 체크포인트 판정

**조건부 PASS**

행 수·기본키·핵심 1:1·1:N 관계·결과 수 합계·고아키·일반 날짜 파싱은 통과했으나, 숙박일 역전 9건, 클릭 호텔 미노출 2건, `booking.hotel_id`–`room.hotel_id` 불일치 2건이 있다. 이를 파생 플래그로 격리하면 다음 단계를 진행할 수 있지만, 원천 정정 여부는 별도 확인이 필요하다. **통계 분석과 합성 데이터 생성은 실행하지 않았다.**

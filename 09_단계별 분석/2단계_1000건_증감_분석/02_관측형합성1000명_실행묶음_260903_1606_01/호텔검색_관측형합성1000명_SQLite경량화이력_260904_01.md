### 제거한 인덱스와 제약

- 사용자 정의 인덱스 4개
  - `idx_syn_event_session_type`
  - `idx_syn_event_search_hotel_type`
  - `idx_syn_search_session_time`
  - `idx_syn_result_search_hotel`

- 최종본은 PK 및 UNIQUE 제약이 없는 읽기 전용 분석용 구조임

### 제거한 반복 텍스트 컬럼

다음 8개 업무 테이블에서 `data_origin` 컬럼을 제거했다.

- `booking`
- `event`
- `hotel`
- `room`
- `search`
- `search_filter`
- `search_result`
- `user`

`data_origin`은 각 테이블 안에서 사실상 단일 값이 반복되어 약 9.57 MiB의 원시 문자열을 차지했다. 출처 정보가 필요하면 원본 DB 또는 외부 실행 묶음 정보를 사용한다.

### 시간 문자열 변경

다음 컬럼의 `YYYY-MM-DD HH:MM:SS KST` 값을 `YYYY-MM-DD HH:MM:SS`로 축약했다.

- `event.event_at`
- `event.session_end_time`
- `search.search_time`
- `user.signup_at`

시각 숫자 자체는 바꾸지 않았고 문자열 끝의 ` KST`만 제거했다. 최종본의 해당 값은 KST 로컬 시각으로 해석해야 한다. 기존 코드가 `.replace(" KST", ...)`를 전제로 하면 최종본 사용 시 시간 파싱 부분을 조정해야 한다.

## 6. 사용 시 주의사항

1. 최종본은 정적·읽기 전용 분석 및 공유 용도다.
2. ID 컬럼은 남아 있어 `JOIN`할 수 있지만, SQLite가 PK 중복이나 NULL을 막지 않는다.
3. 인덱스가 없어 대용량 조건 검색과 조인은 원본보다 느릴 수 있다.
4. 데이터 추가·수정이 필요한 운영 용도에는 원본 또는 PK/인덱스 유지 버전을 사용한다.
5. 시간 문자열은 KST 접미사가 없으므로 KST 로컬 시각이라는 데이터 계약을 별도로 유지한다.

## 전제 2 — 단순 복제 방지

원본 사용자·세션·검색 행을 읽어 복제하지 않는다. 원본 DB는 read-only/query-only 및 해시 확인에만 사용하고, 생성 입력은 `01_probability_parameters.csv`의 집계 Beta 후험모수다. 매 run마다 seed 기반으로 후험확률을 다시 추출한다. 원본 세션 식별자 및 대응표는 스키마에 없고, `distribution_lineage_policy='row-level source lineage removed'`를 전수 기록한다. 비식별 `template_cluster_id`는 원본 키 없이 사전 속성으로 생성한다. 200명 검사에서 완전 동일 논리행 중복 0건, 최대 세션 경로 집중도는 승인 한도 20% 이하였다. `2/43=4.7%`, 검색어 수정 상세진입 원본 `n=10`은 메타데이터에 보존하며 합성 n으로 관측 신뢰구간을 축소하지 않는다.

## 전제 3 — 5,000 pair의 paired A/B

운영 계획은 5,000개 사전 프로필에서 control/treatment 각 1명을 파생해 정확히 10,000명(5,000/5,000)을 만든다. pair 내부의 intent, 지역, 최초 조건, 가격·옵션 제한, 검색 성향, 기준 회복확률, 공통 난수는 동일하며 treatment에서만 노출·정책·선택·조건변경·회복·상세진입 전이를 변경한다. `sample_set_type`은 스키마 CHECK와 테스트로 control/treatment만 허용한다. SG1~SG4는 `SessionSummary.outcome_segment`에만 기록한다.

## 실행 가드와 테스트

dry-run은 짝수 2~200명만 허용한다. production은 정확히 10,000=5,000+5,000, 승인 config 전체 해시, `--confirm-production`, 승인된 빈 폴더의 직접 자식 출력 경로가 모두 맞아야 한다. 다른 규모, 승인되지 않은 폴더, 기존 출력 및 partial 파일은 거부한다. 요구된 17개 테스트를 실행해 17/17 PASS했다. 200명 dry-run에서 integrity check=ok, FK 위반=0, pair 불완전=0, 시간 역전=0, 필수 필드 NULL=0이었다.

# Hotel Search Dashboard — 최종본 작업 폴더

이 폴더를 최종본의 단일 작업 기준으로 사용합니다. `index.html`을 브라우저에서 열면 대시보드와 슬라이드가 인터넷 연결 없이 작동합니다. 최종본 폴더라는 이름은 A/B 결과가 검증 완료되었다는 뜻은 아닙니다. 기존 결과 미연결 표시는 유지합니다.

각 템플릿의 대괄호 안내문을 실제 내용으로 교체하세요. 팀원 행은 인원에 맞춰 추가·삭제할 수 있습니다. 템플릿은 슬라이드 모드의 도입부와 데이터 출처 설명 뒤에 추가되며, 대시보드와 기존 분석 슬라이드는 유지됩니다. 팀원 수·이름·역할·가설 내용은 임의로 채우지 않았습니다.

## 수정 후 반영

저장소 루트에서 다음 명령을 실행합니다. Python 3 표준 라이브러리만 사용합니다.

```sh
python3 final/Hotel_Search_Dashboard/scripts/build.py
python3 final/Hotel_Search_Dashboard/scripts/build.py --check
```

`index.html`은 생성 파일입니다. 직접 수정하지 말고 원본 파일을 수정한 뒤 다시 생성하세요. 결과 파일 하나만 전달해도 대시보드·슬라이드를 열 수 있습니다. 기존 날짜별 초안 폴더는 참고용이며, 이후 수정은 이 최종본 폴더에서 진행합니다.

## 여러 명이 수정할 때

GitHub는 변경 이력을 합치는 방식이며 같은 화면의 실시간 공동 입력을 제공하지 않습니다. 이번 구성은 담당 파일을 분리해 동시 작업의 충돌을 줄입니다.

1. 작업 전 `git fetch origin` 후 최신 `origin/main`에서 개인 브랜치를 만듭니다. 예: `git switch -c presentation/team-yourname origin/main`.
2. 맡은 파일을 수정합니다. 같은 원본 파일을 동시에 수정해야 한다면 담당 범위를 먼저 정합니다.
3. 빌드와 `--check`, 브라우저 확인 후 변경한 원본과 `index.html`만 지정해 커밋합니다. 다른 사람의 파일까지 일괄 추가하지 않습니다.
4. 개인 브랜치를 push하고 PR로 합칩니다. 공유 브랜치에 강제 push하지 않습니다.
5. 두 작업이 합쳐질 때 `index.html` 충돌은 HTML 전체를 수작업으로 합치지 않습니다. 원본 충돌을 먼저 해결한 후 build.py로 재생성합니다.

## 현재 데이터·검증 범위

- 수집 원본 기준: 검색 연결 사용자 41명·43세션·296검색.
- 현재 그래프: 원본 기반 합성 1,000명·1,000세션·6,900검색. 44.72MiB DB의 집계만 포함하며 원시 개인정보·SQLite 파일은 이 폴더에 포함하지 않습니다.
- 원본 44.72MiB DB SHA-256: `9120561ee85705141a92eae74c5015fb2c9a20f0c8d1f6df4d99893952fd1e9f`.
- 10개 기간 선택 × 5개 성과군 선택의 50개 집계가 포함됩니다. 기본 퍼널은 기간만, 별도 비교와 다른 지표는 기간·성과군을 적용합니다.
- 총 34장입니다. 초반은 주제 → 팀원 → 기획 의도 → 논문·데이터셋 연결 대기 → 가상 사이트·설문 → 가설 순서입니다. 주제·기획·수집 방식은 Notion 본문을 반영했고, 팀원·시행착오 등 작성용 템플릿은 유지했습니다. 대본은 기본 닫힘입니다.
- 유의성·신뢰구간·A/B 집단별 결과는 기존 미연결/미산출 상태입니다. 합성 확장이나 성과군 비교를 실험 효과로 해석하지 않습니다.
- 브라우저에서 입력한 목표 KPI는 현재 탭에서만 유지됩니다. 저장소에 저장하거나 다른 사람에게 실시간 동기화하지 않습니다.

세그먼트의 판정식·단위·예외·의도군 연결 상태는 `notes/Segment_Definitions.md`에 정리했습니다. 대시보드 현황 페이지와 슬라이드 25장에서도 확인할 수 있습니다.

Notion 출처와 확인 상태는 `notes/Source_References.md`를 참고하세요.

성과군별 관측 여정 4개와 의도별 제안 흐름 6개를 현황 페이지에 추가했습니다. 슬라이드 28~31장에서 두 종류를 구분해 볼 수 있습니다. 성과군 여정은 기간·성과군 필터에 따라 갱신되며, 의도별 제안 흐름은 문서 기반이라 인원·전환율을 표시하지 않습니다.

슬라이드 16~18장에 10,000명 시뮬레이션 한계·HOLD·수치 해석을 추가했습니다. `notes/Simulation_10K_Limitations.md`에 제공된 전체 표와 출처를 보존했습니다. 1,000명 집계 JSON과 품질 게이트 값은 변경하지 않았습니다.

슬라이드 6~8장에 StayTrace 참여 과정, 제공 스크린샷의 콘솔 현황, 옵션 일치·불일치 실험 요약을 추가했습니다. `assets/`의 두 원본 PNG는 빌드 시 HTML에 내장되므로 index.html 하나로 오프라인 열람할 수 있습니다. 콘솔 수치는 캡처 시점의 참고값이고 현재 집계 JSON을 대체하지 않습니다.

발표 가설은 H1·H5·H4만 표시합니다. 34장 목차는 `notes/Slide_Outline.md` 및 대시보드 00·슬라이드 상단의 목차 메뉴에서 확인할 수 있습니다. 메뉴는 기본 닫힘이며 클릭하면 해당 장으로 이동합니다.

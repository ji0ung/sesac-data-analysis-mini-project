# Hotel Search Dashboard — 최종본 작업 폴더

이 폴더를 최종본의 단일 작업 기준으로 사용합니다. `index.html`을 브라우저에서 열면 대시보드와 슬라이드가 인터넷 연결 없이 작동합니다. 최종본 폴더라는 이름은 A/B 결과가 검증 완료되었다는 뜻은 아닙니다. 기존 결과 미연결 표시는 유지합니다.

## 파일별 담당

| 수정할 내용 | 원본 파일 |
| --- | --- |
| 주제 빈 템플릿 | `slides/topic.html` |
| 팀원 구성 빈 템플릿 | `slides/team.html` |
| 프로젝트 의도 빈 템플릿 | `slides/intent.html` |
| 가설 빈 템플릿 | `slides/hypotheses.html` |
| 대시보드 화면 문구·배치 | `src/dashboard.html` |
| 색상·글꼴·차트 스타일 | `src/dashboard.css` |
| 필터·계산·슬라이드 동작 | `src/dashboard.js` |
| 집계 데이터 | `data/dashboard_slices.json` |
| 발표 대본 | `notes/Presentation_Notes.md` |

각 템플릿의 대괄호 안내문을 실제 내용으로 교체하세요. 팀원 행은 인원에 맞춰 추가·삭제할 수 있습니다. 템플릿은 슬라이드 모드 앞부분에만 추가되며, 대시보드와 기존 분석 슬라이드는 유지됩니다. 팀원 수·이름·역할·가설 내용은 임의로 채우지 않았습니다.

## 수정 후 반영

저장소 루트에서 다음 명령을 실행합니다. Python 3 표준 라이브러리만 사용합니다.

```sh
python3 final/Hotel_Search_Dashboard/scripts/build.py
python3 final/Hotel_Search_Dashboard/scripts/build.py --check
```

`index.html`은 생성 파일입니다. 직접 수정하지 말고 원본 파일을 수정한 뒤 다시 생성하세요. 결과 파일 하나만 전달해도 대시보드·슬라이드를 열 수 있습니다. 기존 날짜별 초안 폴더는 참고용이며, 이후 수정은 이 최종본 폴더에서 진행합니다.

## 여러 명이 수정할 때

GitHub는 변경 이력을 합치는 방식이며 같은 화면의 실시간 공동 입력을 제공하지 않습니다. 이번 구성은 담당 파일을 분리해 동시 작업의 충돌을 줄입니다.

1. 작업 전 `git fetch origin` 후 최신 `origin/main`에서 개인 브랜치를 만듭니다. 예: `git switch -c presentation/team-yourname origin/main`.
2. 맡은 파일을 수정합니다. 같은 원본 파일을 동시에 수정해야 한다면 담당 범위를 먼저 정합니다.
3. 빌드와 `--check`, 브라우저 확인 후 변경한 원본과 `index.html`만 지정해 커밋합니다. 다른 사람의 파일까지 일괄 추가하지 않습니다.
4. 개인 브랜치를 push하고 PR로 합칩니다. 공유 브랜치에 강제 push하지 않습니다.
5. 두 작업이 합쳐질 때 `index.html` 충돌은 HTML 전체를 수작업으로 합치지 않습니다. 원본 충돌을 먼저 해결한 후 build.py로 재생성합니다.

- 10개 기간 선택 × 5개 성과군 선택의 50개 집계가 포함됩니다. 기본 퍼널은 기간만, 별도 비교와 다른 지표는 기간·성과군을 적용합니다.
- 주제·팀원·의도·가설 빈 템플릿 4장과 기존 분석 슬라이드 13장으로 총 17장입니다. 대본·상세 정의는 기본 닫힘입니다.
